# 시빅 정비수첩

`hodu-ho.me/civic/`. 혼다 시빅 1.8 (31버7847, FD1, 2008년식, 등록 2007-12-21)의 소모품 교체 시점과 종합검사 시기를 안내하고, 정비 이력·비용 통계를 보여 준다. 청첩장과 같은 레포에 있지만 코드·스타일은 공유하지 않는 독립 페이지다. 빌드 없음.

## 파일

| 파일 | 역할 |
| --- | --- |
| `data.js` | 데이터 원본. `window.CIVIC_DATA` |
| `logic.js` | DOM 없는 순수 함수(날짜, `calcPart`, CSV 입출력). `window.CivicLogic` |
| `script.js` | 화면 렌더링과 동작 |
| `car.js` | 히어로의 회전하는 시빅 |
| `favicon.svg`, `favicon.png` | 16×16 도트. 조명 받는 은색 혼다 H(위가 넓은 테두리와 H가 위아래로 이어짐). 검정(`#0a0c0e`) 바탕을 16×16 전체에 깐다. png는 32×32 |
| `fonts/` | 도깨비DNR 고딕 woff2와 `OFL.txt` |

`index.html`에서 `data.js` → `logic.js` → `script.js` → `car.js` 순서로 불러온다. 외부 의존성은 Pretendard 웹폰트(jsDelivr, wedding과 같은 v1.3.9)와 요약 탭의 날씨 예보(Open-Meteo, 키 없음)다. 예보는 `settings.area` 좌표로 7일치를 받아 `localStorage`의 `civic:wx`에 3시간 캐시한다. 못 받으면 날씨 줄만 비고 나머지 알림은 그대로 뜬다.

## 운영 방식

- 보기 전용. 정비를 받으면 `data.js`를 직접 고친다. 서버·구글 시트 연동은 보류.
- 편집 기능(추가·수정·삭제 폼, 오늘 교체함, 주행거리 수정, 이슈 완료, 데이터 탭의 백업·CSV)은 코드에 남겨 두고 `script.js`의 `EDIT = false`로 끈다. 버튼을 숨기고 클릭 처리에서도 막는다. 켜면 `localStorage`에 저장하며, 비어 있으면 `data.js`에서 시작한다.
- 주행거리는 `settings.currentKm`과 기준일 `settings.kmDate`로 표시한다. 2026-07-22 기준 259,517km는 보험 마일리지 특약의 최초 주행거리 등록값이다.
- 구글 시트로 갈 경우: 드라이브 커넥터는 CSV로 새 시트를 만들 수만 있고 기존 시트를 덮어쓸 수 없었다. Sheets API나 Apps Script로 직접 읽고 써야 한다. 레포와 사이트가 공개라 Apps Script 주소가 노출되므로 쓰기(필요하면 읽기도)를 비밀 키로 막아야 한다.

## 판단 규칙

- 교체 주기(`calcPart`): ratio = max(사용 km ÷ 주기 km, 경과 기간 ÷ 주기 개월). 기준 없음 `none` / ratio ≥ 1 `over` / ratio ≥ 0.85 `soon` / 그 외 `ok`.
- 오늘 교체함(편집 켰을 때): lastDate = 오늘, lastKm = 현재 주행거리.
- 종합검사 가능 기간: 다음 검사일 −90일 ~ +31일.
- 누적 정비비는 자비 정비만 센다. 보험 수리·견적은 제외(통계 탭에서 보험 포함 토글). 보험료는 `policies`에 따로 있어 들어가지 않는다.
- 요약의 누적 정비비는 100만원 단위 반올림("약 700만원")으로 보이고, 누르면 원 단위로 바뀐다. 요약의 최근 정비에는 건별 금액을 싣지 않는다. 건별 금액은 정비 이력·통계 탭에 있다.
- 주행거리 추이 그래프는 정비·검사 기록의 주행거리에 `settings`의 `kmDate`·`currentKm`을 한 점으로 더한다.

## 요약 대시보드

- 위 타일 4개: 종합검사 D-day, 자동차보험 만기 D-day와 마일리지 남은 거리, 소모품 상태 개수, 누적 정비비. 760px 이하에서 2열.
- "요즘 챙길 것"은 `logic.js`의 `careTips`가 만든다. 위험도(`over` > `soon` > `ok`) 순으로 정렬한다.
  - 기록: `kmDate`가 30일보다 오래되면 주행거리 갱신.
  - 기한: 보험 만기 45일 이내면 마일리지 정산 사진 등록·갱신 비교. 종합검사 기간이면 검사, 기간 시작 180일 이내이고 열린 이슈에 "누유"가 있으면 검사 전 정비.
  - 날씨(`weatherTips`, 7일 예보 중 가장 추운·비 많은·더운 날 기준): 눈, 최저 −5° 이하 혹한, 0° 이하 결빙, 5° 이하 공기압, 하루 20mm 이상 비, 최고 33° 이상 폭염.
  - 시기: 월별 고정 문구(`SEASON`). 1월 자동차세 연납 신청, 3~4월 하부 세차, 5월 에어컨, 6월 장마 대비, 7~8월 냉각수·실내 고온, 9월 블랙박스, 10~2월 겨울 준비·겨울.
  - 매달: 누유 이슈가 열려 있으면 엔진오일 양·타이어 공기압. 기록이 없는 점검이라 교체 주기 항목 대신 여기 둔다.
- 날씨 코드는 WMO 기준으로 맑음·구름·흐림·안개·비·눈·뇌우로 줄인다(71~77·85~86만 눈).
- 날씨 아이콘은 16×16 도트(`script.js`의 `WXI` 격자 문자열 → SVG 사각형, 2배인 32px로 표시). 차와 같은 짙은 1px 외곽선(`#1b2026`)이라 밝은 테마에서는 흰 구름 테두리가 되고 어두운 테마에서는 배경에 묻힌다. 외곽선 없는 안은 밝은 테마에서 구름·눈이 사라져 버렸다. 해의 햇살 8개는 모두 2px 굵기, 상하좌우는 3px·대각선은 2×2 블록. 아이콘 이름은 화면에서 숨긴 글자(`.sr`)로 남긴다.

## 데이터 모델 (`data.js`)

- `records`: date, km, shop, shopType(honda|general), kind(repair|insurance|estimate), title, items[], amount, note
- `parts`: name, intervalKm, intervalMonths, lastDate, lastKm, note
- `inspections`: date, km, result, nextDate, note
- `issues`: text, status(open|done), since
- `policies`: insurer, start, end, premium, payMethod, coverage[], terms[], mileageStartKm, mileageStartDate, mileageLimitKm, note (자동차보험 가입 기록. 요약 탭에는 만기 D-day, 보험사·만기일, 마일리지 특약 남은 거리만 보이고 보험료·담보·메모는 정비 이력 탭에 있다. 특약 목록은 데이터에만 있다)
- `settings`: plate, model, currentKm, kmDate, area(날씨 예보 지역 이름·위경도, 시 단위 좌표만 넣는다). 편집을 켜면 주행거리 수정이나 더 큰 주행거리의 정비 기록 저장 때 kmDate도 함께 바뀐다.

## 데이터 주의점

- 교체 주기는 공식 취급설명서 확인 전이다. 아래 "교체 주기 출처"의 웹 참고값이며, 출처가 없는 항목은 처음 넣은 임시값 그대로다.
- 2025-10-13 정비(2,611,290원): 문서 하단 손글씨 `−961,290 / 1,650,000`이 실제 지불액을 뜻할 수 있으나 문서로 확정할 수 없다. 앱은 2,611,290으로 집계한다. 수리비 누계 6,914,150원(수리 11건), 1,650,000이 실제라면 5,952,860원.
- 2024-04-29 보험 수리(3,385,030원)의 본인 부담금은 문서에 없다.
- 2026-03-12 좌측 사이드미러(466,950원)는 시행했으나 명세서가 없어 견적서 금액과 견적일로 정비 기록(`r20260312-mirror`)에 넣었다. 같은 날 스풀밸브 명세서의 "사이드미러 교환 예정" 문구는 원문이라 그대로 둔다.
- 2025-07-02 견적(961,290원)은 2025-10-13 정비에 포함돼 있어 견적으로 남긴다. 정비로 바꾸면 이중 집계된다.
- 2025-12-26 종합검사: 적합이지만 헤드·오일팬·엔진 앞 케이스 누유(심함) 보완 권고, 자기진단 센서 점검은 "진단불가(통신 이상)".
- 주민등록번호·차대번호는 넣지 않는다. 레포와 사이트가 공개다.
- 타이어 장착일(2026-03-27)과 모델은 T맵 all my T 화면 기준이다. 장착 시 주행거리·금액·정비소는 없어 정비 이력에는 넣지 않았다.
- 보험 가입 기록에는 피보험자 이름, 주민등록번호, 운전자 연령 범위(생년월일이 드러남)를 넣지 않는다. 특별약관 중 연령 한정 특약은 연령대가 드러나 넣지 않았다. 이전 가입 이력은 문서가 없어 현재 계약(2026-07-11 ~ 2027-07-11)만 있다. 2024-04 자차 청구는 교보AXA였다.

### 교체 주기에 두는 항목

교체 주기에는 정해진 주기로 바꾸는 소모품과 점검만 둔다. 엔진마운트·토크로드, 앞 로우암·스태빌라이저 링크, 워터펌프·서모스탯은 상태를 보고 교체하는 부품이라 주기 막대가 오해를 불러 뺐다. 교체 이력은 정비 기록에 있다. 자동차세도 행정 기한이라 뺐다.

추가한 점검 항목은 타이어 교체, 브레이크 패드·디스크, 와이퍼, 휠 얼라인먼트다. 안전과 직결되거나, 기한을 놓치면 손해이거나, 최근 작업과 맞물린 것만 남겼다. 와셔액, 공기압, 에어컨 냉매, 전구류, 리콜 확인, 등속조인트 부츠, 미션마운트, 타이어 위치교환, 쇽업쇼바·부싱, 연료필터는 정해진 주기가 없거나 중요도가 낮아 뺐다. 모두 출처 없는 임시 주기이고, 마지막 교체일·주행거리가 비어 있으면 "기록 없음"으로 뜬다. 확인한 날짜를 `data.js`에 넣어야 알림이 시작된다. 타이밍 체인(R18A, 무교환)과 밸브 간극은 주기가 없어 넣지 않았다.

## 폰트

- 히어로(제목·번호판·계기판)는 도깨비DNR 고딕(`.px`), 나머지는 Pretendard.
- 도깨비DNR은 `~/GitHub/font` 릴리스 v1.0.2의 woff2를 직접 호스팅한다.
- 16×16 셀 비트맵 기반이라 16px·32px에서만 선명하다. 다른 크기를 쓰지 않는다.
- GSUB이 없어 `tnum`이 안 된다. 숫자를 세로로 정렬해야 하는 곳은 Pretendard `tabular-nums`를 쓴다.
- 차트는 SVG `viewBox`로 늘어나므로 픽셀 폰트를 쓰지 않는다.

## 히어로 시빅 (`car.js`)

- 라이브러리 없이 캔버스 `ImageData`에 직접 래스터라이즈한다. 로프트(단면 연결)로 차체·유리 부분, 12각 실린더로 바퀴.
- 형상은 FD 세단 청사진(getoutlines.com `honda-civic-4dr-2006.gif`, CC BY 4.0) 옆모습을 휠베이스 2,700mm = 341px(약 7.9mm/px)로 환산해 `SILL`·`BELT`·`HALF`·`ROOF` 프로파일로 옮겼다. 프로파일은 단조 3차 보간, 단면은 4cm 간격으로 자동 생성.
- 디테일 참고 사진: 위키미디어 커먼즈 `Honda CIVIC 1.8GL (DBA-FD1) front/rear.jpg`(CC BY-SA 4.0).
- 차는 전기형(2006~2008) 국내 사양 FD1. 전·후기형 차이는 앞범퍼·그릴·테일램프뿐이라 실루엣은 같다.
- 완벽 재현보다 특징 살리기가 목표다.
  - 차체 어깨와 유리 부분 단면은 슈퍼타원으로 굴렸다. 어깨선은 휠 아치와 무관하게 보닛 높이만 따른다.
  - 탑승부 높이는 실측의 1.5배(`LIFT`)다.
  - 앞유리 밑단(카울)은 실측보다 12cm 뒤(x=1.17m)다.
- 램프·그릴·흡기구·테일램프·휠 스포크는 면 재질이 아니라 픽셀마다 3D 위치로 칠하는 데칼(`facePaint`, `spokes`)이다. 앞모습 치수는 청사진 정면도 실측(약 5.8mm/px): 헤드라이트 지상 0.58~0.78m, 중심에서 0.44~0.86m, 그릴 0.57~0.68m, 하단 흡기구 0.29~0.45m.
- 휠은 FD1 1.8 순정 은색 5스포크.
- 유리·A필러·지붕 레일은 벨트~지붕 높이 비율(u)로 픽셀마다 칠한다(`glassPaint`). 옆 유리는 u 0.8 아래, 지붕 레일은 그 위다. 앞·뒷유리는 옆 위치(|z|)로 경계를 잡아 아래가 넓은 사다리꼴(앞유리 0.70m→0.53m)이고, A필러는 그 바깥 0.11m 띠다. 위 끝이 지붕 레일 위치와 맞아 이어진다.
- 명암은 3단계 + 팔레트. 위를 향한 면(법선 y > 0.8: 보닛·지붕·덱)은 늘 가장 밝은 톤이다. 명암 경계가 곡면을 가로지르면 굴곡처럼 보여서다.
- 실루엣과 깊이 차 0.35m 이상인 곳에 1px 외곽선.
- 그림자는 바닥(y=0)에 놓인 슈퍼타원(반축 2.5m × 1.12m, 지수 2.6)이다. 픽셀마다 화면 좌표를 바닥면으로 되돌려 판정하므로 차와 함께 돈다. 색은 `--bg`를 어둡게 곱한 두 톤(밝은 테마 0.9·0.8배, 어두운 테마 0.55·0.3배, 안쪽 r < 0.55가 더 어둡다)이라 테마를 따른다. `--muted`처럼 테마마다 명암이 뒤집히는 색을 섞으면 어두운 테마에서 가운데가 밝아진다.
- 뒷면 데칼(참고 사진 기준): 테일램프는 뒷면 수직부 0.62~0.84m에 둥근 렌즈 두 개, 램프 사이에 0.75~0.8m 회색(`hub`) 가로선, 그 위 0.86~0.95m에 은색 엠블럼. 범퍼는 차체색 그대로 둔다. 번호판·트렁크 이음매·반사판은 뒷면이 화면에서 10px 남짓이라 노이즈가 되어 넣지 않는다.
- 내부 해상도 가로 최대 150px × 56px, CSS로 3배(600px 이상은 4배) 정수 확대. 12fps로 끊어서 회전하고 드래그로 돌린다.
- `prefers-reduced-motion`이면 3/4 앵글로 정지하고, 화면 밖이거나 탭이 숨으면 멈춘다.
- 이스터에그: 차를 더블탭(320ms 안에 6px 이내 두 번 탭)하면 정지 앵글로 돌아 0.18m 물러섰다가 앞으로 가속해 화면 밖으로 나가고, 0.6초 뒤 뒤쪽에서 감속하며 들어와 제자리에 선다(약 2.3초). 차체 x에 `DX`를 더해 움직이고, 그림자도 같은 `DX`로 판정한다. 달리는 동안은 12fps 제한 없이 매 프레임 그린다. `prefers-reduced-motion`이면 동작하지 않는다.
