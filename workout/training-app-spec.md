# 트레이닝 앱 명세

> 개인용 트레이닝 앱(hodu-home)의 단일 명세. §1–§9는 루틴 추천 규칙 엔진, §10은 어시스턴트 대화, §11은 UX, §12는 구현 순서, §13은 미정 항목.
> 시각 요소(색·타이포·간격)는 별도 스타일 가이드에서 정의.
> 상체·하체·풀업처럼 성격이 다른 세션을 하나의 구조로 다루고, 운동과 세션 종류를 계속 추가할 수 있게 하는 것이 목표.
> 어시스턴트 대화(§10)는 이 문서와 최근 기록을 컨텍스트로 쓴다.

---

## 1. 핵심 개념

| 개념 | 설명 |
|---|---|
| **Exercise** | 개별 운동 (랫풀다운, 덤벨 프레스, 스쿼트 …). 카탈로그로 관리. |
| **Pattern** | 동작 유형 (수직 당기기, 수평 밀기, 힌지 …). 템플릿·대체·균형의 기준. 주동근·보조근과 연결 (§2). |
| **Session Template** | 세션 종류(상체/하체/풀업 …)별 **패턴 슬롯** 목록. 운동을 직접 고정하지 않음. |
| **Progression Model** | 운동별 증량 방식 (더블 프로그레션, 선형). |
| **Session Log** | 실제 수행 기록. 추천의 입력. (`workout_YYYY-MM-DD.json` 형식) |

**설계 원칙**: 템플릿은 "패턴 슬롯"으로 정의하고, 슬롯마다 들어갈 수 있는 운동은 카탈로그에서 고른다.
그래야 딥을 푸시다운으로, 풀업을 랫풀다운으로 바꾸는 것 같은 교체를 규칙으로 처리할 수 있고, 하체나 새 세션 종류를 추가해도 구조가 바뀌지 않는다.

## 2. 패턴과 근육

근육 관련 정의는 **쓰는 곳에 따라 세 층**으로 나눈다. 층마다 단위가 일정해야 한다.

| 층 | 단위 | 어디에 쓰나 |
|---|---|---|
| **pattern** | 동작 유형 (§2.1) | 템플릿 슬롯(§7), 대체 추천(§8), 균형 계산(§5) |
| **muscle** | 개별 근육, 한 가지 세밀도 (§2.2) | 회복 계산(§6). 패턴마다 주동근·보조근으로 연결 |
| **region** | 큰 신체 부위 (§2.3) | 화면 표시와 기록 필터만 ("오늘 쓴 부위"). 규칙 계산에는 쓰지 않음 |

### 2.1 패턴 → 주동근 / 보조근

| pattern | 설명 | 주동근 (primary) | 보조근 (secondary) |
|---|---|---|---|
| `vertical_pull` | 위→아래 당기기 | lats | biceps, middle_back, forearms |
| `horizontal_pull` | 앞→몸쪽 당기기 | middle_back, lats | biceps, rear_delts, traps |
| `horizontal_push` | 앞으로 밀기 | chest | front_delts, triceps |
| `vertical_push` | 위로 밀기 | front_delts | side_delts, triceps, traps |
| `rear_delt` | 후면 삼각근 고립 | rear_delts | middle_back, traps |
| `lateral_delt` | 측면 삼각근 고립 | side_delts | traps |
| `elbow_extension` | 삼두 고립 | triceps | — |
| `elbow_flexion` | 이두 고립 | biceps | forearms |
| `squat` | 무릎 주도 | quadriceps, glutes | adductors, hamstrings, lower_back |
| `hinge` | 고관절 주도 (데드리프트, RDL) | hamstrings, glutes | lower_back, traps, forearms |
| `lunge` | 한 발 하체 | quadriceps, glutes | hamstrings, adductors |
| `knee_extension` | 대퇴사두 고립 | quadriceps | — |
| `knee_flexion` | 햄스트링 고립 | hamstrings | calves |
| `calf` | 종아리 | calves | — |
| `core` | 코어 | abdominals | lower_back |
| `cardio` | 유산소 (사이클 등) | — | — (회복 계산 제외) |

- 운동이 패턴 기본값과 다르면 카탈로그에서 `muscles`로 덮어쓴다 (§3.1). 예: 클로즈그립 벤치는 triceps를 primary로.
- **균형 계산용 대분류**
  - 상체: `push` = horizontal_push, vertical_push, elbow_extension / `pull` = vertical_pull, horizontal_pull, rear_delt, elbow_flexion
  - 하체: `knee_dominant` = squat, lunge, knee_extension / `hip_dominant` = hinge, knee_flexion

### 2.2 muscle 어휘

[free-exercise-db](https://github.com/yuhonas/free-exercise-db)(퍼블릭 도메인)의 `primaryMuscles`/`secondaryMuscles` 어휘를 따른다. 공백은 `_`로 바꾼다.

`abdominals`, `abductors`, `adductors`, `biceps`, `calves`, `chest`, `forearms`, `glutes`, `hamstrings`, `lats`, `lower_back`, `middle_back`, `neck`, `quadriceps`, `traps`, `triceps`, 그리고 어깨 3개(아래).

- **바꾼 점 하나**: 원본의 `shoulders`는 `front_delts`, `side_delts`, `rear_delts`로 나눈다. 프레스(전면)와 리버스 펙덱(후면)은 회복이 겹치지 않아서, 하나로 묶으면 회복 경고가 틀어진다.
- 데이터셋에서 운동을 가져올 때는 `shoulders`를 운동에 맞는 쪽으로 바꿔 넣는다.

| region | muscles |
|---|---|
| 가슴 | chest |
| 등 | lats, middle_back, lower_back, traps |
| 어깨 | front_delts, side_delts, rear_delts |

| 하체 | quadriceps, hamstrings, glutes, adductors, abductors, calves |
| 코어 | abdominals |
| 기타 | neck |

## 3. 운동 카탈로그

### 3.1 필드

```yaml
id: seated_cable_row
name: 시티드 케이블 로우
pattern: horizontal_pull
# muscles:                   # 선택. 없으면 패턴 기본값(§2.1)
#   primary: [middle_back, lats]
#   secondary: [biceps, rear_delts, traps]
equipment: cable_machine
equipment_id: gym_a_row_01   # 같은 기구 안에서만 무게 비교 (도르래 비율 차이)
unit: kg                     # kg | lb | min
weight_basis: total          # total | per_side (덤벨)
increment: 2.5               # 1단계 증량 폭 (unit 기준)
rep_range: [8, 10]           # 더블 프로그레션 범위
default_sets: 3
rest_sec: 90
progression: double          # double | linear | none
difficulty: 1                # 1 쉬움 ~ 3 기술 필요 (대체 추천 시 사용)
```

### 3.2 현재 등록 운동과 기준값

| id | pattern | unit | increment | rep_range | sets | rest | progression | 현재 작업 무게 |
|---|---|---|---|---|---|---|---|---|
| `lat_pulldown` | vertical_pull | kg | 2.5 | 8–10 | 3 | 90 | double | 35 (평소 40) |
| `assisted_pullup` | vertical_pull | kg (보조) | -5 | 6–8 | 6 | 150 | double | 미측정 (추정 보조 40) |
| `dumbbell_press` | horizontal_push | kg (per_side) | 2 | 8–10 | 3 | 120 | double | 12 |
| `cable_pushdown` | elbow_extension | kg | 2.5 | 10–12 | 3 | 75 | double | 12.5 |
| `seated_cable_row` | horizontal_pull | kg | 2.5 | 8–10 | 3 | 90 | double | 30 |
| `reverse_pec_deck` | rear_delt | lb | 10 | 10–15 | 3 | 60 | double | 50 |
| `deadlift` | hinge | kg | 2.5 | 5 (고정) | 4 | 150 | linear | 80 |
| `assisted_dip` | horizontal_push | kg (보조) | -5 | 6–8 | 3 | 90 | double | 미측정 (보조 50~55부터 동작 익히기) |
| `leg_press` | squat | kg | 10 | 10–12 | 3 | 120 | double | 70 |
| `leg_curl` | knee_flexion | lb | 10 | 10–12 | 3 | 75 | double | 50 |
| `leg_extension` | knee_extension | lb | 10 | 12–15 | 3 | 75 | double | 50 |
| `stationary_bike` | cardio | min | — | — | — | — | none | 15분 |

> 레그 프레스·레그 컬·레그 익스텐션 기준값은 2026-11-11 첫 하체 세션 실측. 스쿼트·카프 레이즈 등은 실측 후 추가.

## 4. 증량 규칙 (Progression)

### 4.1 더블 프로그레션 (`double`)

대부분의 머신·덤벨·케이블 운동에 적용. 본세트(`is_warmup: false`)만 계산한다.

```
min, max = rep_range
본세트 전부 reps >= max      → 다음 세션 weight + increment, 목표 reps = min
본세트 전부 reps >= min      → 무게 유지, 목표 reps +1 (max까지)
reps < min 인 세트가 2개 이상 → 무게 유지 (2회 연속이면 increment만큼 감량)
```

- 보조 운동(어시스트 딥, 어시스트 머신)은 increment가 음수 → "증량" = 보조를 줄이는 것.
- lb 기구는 lb 단위 그대로 증량하고, 표시할 때만 kg 환산(× 0.4536)을 같이 보여준다.

### 4.2 보조 무게 운동 — 풀업·딥

- 어시스트 머신의 보조 무게로 관리하고, 증량은 더블 프로그레션(§4.1)을 따른다 (increment 음수 = 보조 감소).
- **완전 가동범위(턱이 바 위)만 유효 반복(`reps`)으로 센다.**
- 보조를 줄인 직후 rep_range 하한을 못 채우면 → 네거티브 풀업 3세트를 보조로 추천.

### 4.3 선형 (`linear`) — 데드리프트 등 주요 복합 운동

- 고정 반복(5회) × 4–5세트.
- 본세트 전부 5회 달성 + 자세 이상 없음 → +2.5kg.
- 5회를 못 채운 세트가 생기면 → 무게 유지. 2회 연속 실패 시 10% 감량 후 다시 올린다.
- 본세트 수가 목표 세트보다 적으면 증량하지 않는다 (더블 프로그레션도 같다).
- 웜업은 2세트 고정: 빈 봉(20kg) × 10, 작업 무게의 약 60~65% × 5.

### 4.4 무게 탐색 (기준값 없는 운동) — 재기획 예정

> 현재 앱에서는 제외. 기록이 없는 운동은 카탈로그의 추정 무게(`estimate`)를 목표로 추천하고, 웜업 세트는 세트 수정에서 표시한다.

처음 하는 운동이나 기구가 바뀐 경우(`equipment_id`가 새로운 경우).

```
1세트: 추정 무게로 rep_range 상한까지 수행
  여유 있음 → +1 increment (가볍게 느껴진 정도가 크면 +2)
  적당함   → 이 무게를 작업 무게로 확정
  무거움   → -1 increment
확정 전 세트는 is_warmup: true 로 기록
```

> 2026-11-07 덤벨 프레스 8 → 10 → 12kg, 리버스 펙덱 30 → 50lb가 이 흐름.

## 5. 균형 규칙

최근 **7일** 기준, 본세트 수로 계산.

| 체크 | 기준 | 알림 |
|---|---|---|
| push : pull | pull ≥ push (권장 1:1 ~ 1:1.5) | push가 pull보다 많으면 "당기기 추가 권장" |
| 수평 vs 수직 당기기 | 둘 다 1세트 이상 | 한쪽이 0이면 해당 패턴 추천 |
| 수평 vs 수직 밀기 | 둘 다 1세트 이상 | `vertical_push` 0이면 숄더 프레스 추천 |
| 팔 고립 | elbow_flexion, elbow_extension 각 1세트 이상 | 0인 쪽 추천 (낮은 우선순위) |
| 하체: squat vs hinge | 둘 다 1세트 이상 | 한쪽이 0이면 해당 패턴 추천 |
| 하체: knee_dominant vs hip_dominant | 세트 비율 1:1 근처 | 2배 이상 차이 나면 알림 |

## 6. 회복 규칙

| 규칙 | 내용 |
|---|---|
| 근육 부하 | 본세트 1세트당 primary 근육 1.0, secondary 근육 0.5로 누적. 한 근육의 부하가 6 이상이면 **48시간** 안에 그 근육을 primary로 쓰는 운동에 경고 |
| 풀업 빈도 | `assisted_pullup` 은 이틀에 한 번. 상체 세션에서 vertical_pull을 했다면 그날을 풀업 날로 간주 |
| 하체 → 하체 | 하체 세션 사이 최소 48시간 |
| 당일 순서 | 같은 패턴을 먼저 했으면 그 뒤 같은 패턴 운동은 무게 하향 추천 (예: 랫풀다운 후 풀업 → 개수 감소 예상, 생략 허용) |

## 7. 세션 템플릿 (패턴 슬롯)

슬롯 = `{pattern, priority, sets}`. `priority`: `core`(필수) / `main` / `optional`(시간 남을 때).
시간이 부족하면 optional → main 순으로 뺀다.

**목표 시간 맞추기** (설정의 `근력 운동 목표 시간`, 기본 35분. 유산소는 계산에서 뺀다)
- 남은 예상 시간 = 운동마다 `남은 세트 × (휴식 + 40초)`의 합. 경과 시간은 `시작`을 누른 때부터 잰다.
- 세션을 만들 때와 세트를 기록할 때마다 `경과 + 남은 예상`이 목표를 넘으면, 아직 시작하지 않은 운동을 뒤에서부터 optional → main 순으로 `생략` 처리한다. core·진행 중·기록이 있는 운동은 빼지 않는다.
- 뺀 운동은 휴식 화면에 알리고, 세션 목록에서 되살릴 수 있다. 되살린 운동은 다시 자동으로 빼지 않는다.
- 진행 표시에 `경과/목표 분`을 보여주고, 목표를 넘기면 빨간색으로 바꾼다. 목표 시간이 되면 휴식 화면에 안내를 띄우고 `세션 종료`를 주 버튼으로 둔다.

### 7.1 상체 (`upper`, 30–40분)

| 순서 | pattern | priority | 기본 운동 | 대체 후보 |
|---|---|---|---|---|
| 1 | vertical_pull | core | assisted_pullup | lat_pulldown |
| 2 | horizontal_push | core | dumbbell_press | bench_press, assisted_dip |
| 3 | horizontal_pull | core | seated_cable_row | dumbbell_row |
| 4 | elbow_extension | main | cable_pushdown | assisted_dip |
| 5 | rear_delt / lateral_delt | main | reverse_pec_deck | lateral_raise_machine, cable_lateral_raise |
| 6 | vertical_push / elbow_flexion | optional | (균형 규칙 결과로 선택) | dumbbell_shoulder_press, dumbbell_curl |
| + | cardio | optional | stationary_bike 15분 | — |

- 순서 재배치 규칙: primary 근육이 겹치는 슬롯이 연달아 오지 않게 push/pull을 번갈아 배치.

### 7.2 하체 (`lower`, 30–40분) — 초안

| 순서 | pattern | priority | 기본 운동 | 대체 후보 |
|---|---|---|---|---|
| 1 | hinge 또는 squat (번갈아) | core | deadlift | romanian_deadlift / squat, leg_press |
| 2 | 1번과 반대 패턴 | core | leg_press | squat, hack_squat |
| 3 | knee_flexion | main | leg_curl | — |
| 4 | lunge 또는 knee_extension | main | leg_extension | split_squat, walking_lunge |
| 5 | calf / core | optional | calf_raise | plank, cable_crunch |
| + | cardio | optional | stationary_bike 15분 | — |

- 데드리프트가 있는 날은 1번을 hinge로 고정하고, 2번은 무릎 주도 운동.
- 앱에는 실측한 운동만 넣었다: deadlift → leg_press → leg_curl → leg_extension → stationary_bike. 5번(calf / core)과 대체 후보는 실측 후 추가.

### 7.3 풀업 (`pullup`, 홈)

| 순서 | pattern | priority | 운동 |
|---|---|---|---|
| 1 | — | core | 데드행 30초 (웜업) |
| 2 | vertical_pull | core | assisted_pullup 6 × 6–8 |
| 3 | vertical_pull | optional | 네거티브 풀업 3세트 (보조 무게 하향 직후) |

### 7.4 새 세션 종류 추가

템플릿 파일에 슬롯 목록만 추가하면 된다 (예: `full_body`, `push`, `pull`). 증량·균형·회복 규칙은 그대로 적용.

## 8. 대체 규칙

사용자가 운동을 건너뛰거나 "어렵다"고 할 때.

1. 같은 `pattern` 안에서 `difficulty`가 더 낮은 운동으로 대체.
2. 같은 pattern 후보가 없으면 primary 근육이 겹치는 고립 운동으로 대체 (예: 딥 → 푸시다운. 딥은 카탈로그에서 `muscles.primary`에 chest, triceps를 둔다).
3. 생략 시 균형 규칙에서 해당 패턴이 부족해지면 다음 세션에서 우선 추천.

## 9. 입출력

### 9.0 횟수 입력 방식

입력 방식을 따로 고르지 않는다. 세트 화면의 카운터 하나에서 두 방식을 다 쓴다. 카운터는 0에서 시작한다.

| 동작 | 방식 | 어울리는 상황 |
|---|---|---|
| 세기 | 가운데 숫자 영역을 반복마다 탭해서 +1 | 반복마다 질을 판단할 때, 몇 개 할지 모를 때 |
| 한 번에 | 하단 `+N` 버튼으로 세트당 목표 횟수(N)를 한 번에 더한다 | 기구를 쥐고 있어서 중간에 폰을 못 만질 때 |

- 하단에 `되돌리기 / +N` 두 버튼을 나란히 둔다. `되돌리기`는 직전 동작(+1, +N)을 하나씩 취소한다.
- 제대로 수행했는지는 운동하는 사람이 판단한다. 제대로 하지 못한 반복은 세지 않고, 부분 반복을 따로 기록하지 않는다.
- 세트 기록의 `input_mode`는 `+N`을 썼으면 `batch`, 아니면 `tap`. 추천 규칙은 이 값과 무관하게 `reps`만 본다.

**세트 체감 입력 (`feel`)**: 세트 기록 직후 `가벼움 / 적당 / 무거움` 버튼을 띄운다 (건너뛰기 가능).
- 무게 탐색(§4.4)의 판단 입력으로 쓴다.
- 더블 프로그레션(§4.1)에서 상한 횟수를 채웠더라도 `무거움`이면 증량을 한 세션 미룬다.

### 9.1 입력: 세션 기록

`workout_2026-11-07.json` 구조를 따른다. 추천에 필요한 최소 필드:

```
date, session_type,
exercises[].exercise_type, equipment_id, unit, weight_basis,
exercises[].sets[].set_number, weight, reps, is_warmup,
exercises[].sets[].input_mode   // "tap" | "batch"
exercises[].sets[].feel         // "light" | "ok" | "heavy" | null
```

- 예시 파일(2026-11-07)은 `input_mode`·`feel`·`equipment_id` 도입 전 기록이다. 없는 필드는 `null`로 읽는다.

### 9.2 출력: 다음 세션 추천

```json
{
  "session_type": "upper",
  "date": "2026-11-09",
  "estimated_min": 38,
  "items": [
    {
      "slot": 1,
      "exercise_type": "lat_pulldown",
      "weight": 37.5, "unit": "kg",
      "sets": 3, "reps_target": 8, "rest_sec": 90,
      "reason": "지난 세션 35kg × 10 × 3 전부 상한 달성 → +2.5kg"
    }
  ],
  "warnings": ["최근 7일 vertical_push 0세트 → 숄더 프레스 추천"]
}
```

- `reason`은 항상 채운다 (어떤 규칙이 적용됐는지). 어시스턴트(§10)가 이걸 근거로 설명·수정한다.

## 10. 어시스턴트 대화

운동 중에 앱 안에서 Claude와 대화하며 루틴을 조정한다. ("랫풀다운 먼저 했어", "딥 어려워", "하나 더 넣어줘", "파운드로 돼 있는데" 같은 요청)

### 10.1 연결 방식

- claude.ai의 채팅 세션은 외부 앱에서 이어 쓸 수 없다. 앱이 **Claude API(Messages API)를 직접 호출**하고, 대화 기록은 앱이 저장한다.
- **대화 스레드 = 운동 세션 하나.** 세션 시작 때 새 스레드를 열고, 세션 `draft`와 같이 저장한다. 앱을 닫았다 열어도 이어진다.
- **세션 사이의 연속성은 코치 노트로.** 세션 종료 때 Claude가 그 대화를 짧게 요약해 `coach_notes`에 추가한다 (예: "딥은 아직 어려워함, 푸시다운으로 대체", "로우 30kg이 적정"). 다음 세션의 시스템 프롬프트에 넣는다. 사용자가 노트를 직접 보고 고칠 수 있게 한다.
- 모델: 운동 중 대화는 응답 속도가 중요하므로 Sonnet급. 세션 요약은 같은 모델이나 더 가벼운 모델.
- API 키: 레포가 공개이므로 키를 코드에 넣지 않는다. 설정 화면에서 입력해 기기에만 저장하거나, 작은 서버리스 프록시를 둔다.

### 10.2 컨텍스트

| 위치 | 내용 | 갱신 |
|---|---|---|
| 시스템 프롬프트 | 역할(트레이닝 코치), 이 명세의 §1–§9, 사용자 기본 정보(체중, 보유 기구, 기구 단위), `coach_notes` | 세션 시작 때 |
| 매 요청에 첨부 | **현재 세션 상태 JSON**: 운동 목록과 상태, 기록된 세트, 지금 운동, 입력/휴식 모드, 경과 시간 | 매 요청 |
| 세션 시작 때 1회 | 최근 2~4주 세션 기록, 규칙 엔진 추천(§9.2) | 세션 시작 때 |
| 대화 기록 | 이 세션의 사용자·Claude 메시지 | 누적 |

세션 상태를 매번 붙이므로, 사용자가 "2세트 끝"처럼 짧게 말해도 Claude가 어느 운동 몇 세트째인지 안다.

### 10.3 도구 (앱 조작)

Claude는 답만 하지 않고 **도구 호출로 앱 상태를 바꾼다.** 예: "12kg이 적당한 듯" → 남은 세트 목표를 12kg으로 수정.

| 도구 | 하는 일 |
|---|---|
| `set_target` | 운동의 목표 무게·횟수·세트·휴식 수정 (지금 운동 또는 남은 세트만) |
| `swap_exercise` | 운동 대체 (§8 후보 안에서 우선) |
| `add_exercise` | 운동 추가 (위치 지정) |
| `skip_exercise` | 운동 생략 |
| `reorder` | 운동 순서 변경 |
| `log_set` | 세트 기록 (사용자가 말로 알려준 경우: "30kg 10회 했어") |
| `edit_set` | 기록된 세트 수정 |
| `add_note` | 운동이나 세션에 메모 |
| `get_history` | 특정 운동의 과거 기록 조회 |

- 도구가 바꾼 내용은 대화 아래에 **변경 칩**으로 보여주고 탭 한 번으로 되돌릴 수 있게 한다. 확인 없이 바로 적용한다 (운동 중에는 확인 단계가 번거롭다).
- 무게는 규칙 엔진 값을 기본으로 하고, Claude가 바꿀 때는 이유를 같이 남긴다 (§9.2의 `reason`과 같은 형식).

### 10.4 화면

- 운동 화면 어디서든 열 수 있는 **대화 시트**. 입력/휴식 영역을 가리지 않도록 반쯤 올라오는 시트.
- 답변은 짧게. 무게·횟수·세트를 항상 숫자로 명시 (운동 중에 바로 따라 할 수 있게).
- 텍스트 입력 외에 **음성 입력**을 고려 (§13).

### 10.5 규칙 엔진과의 관계

- 규칙 엔진(§4–§8)은 그대로 기본값을 만든다. 어시스턴트는 그 결과를 상황에 맞게 조정하는 역할.
- 어시스턴트가 바꾼 값도 세션 기록에 남으므로, 다음 세션의 규칙 엔진 계산에 그대로 반영된다.

## 11. UX

### 11.1 화면 구조

하루 세션은 여러 운동으로 이루어진다. **운동 화면에는 지금 하는 운동 하나만** 보여주고, 운동 사이를 오간다.

```
세션 시작 ──▶ 운동 화면 (운동 1) ──▶ 운동 화면 (운동 2) ──▶ … ──▶ 세션 요약
                 ▲      │
                 └ 세션 목록 화면 (이동·순서 변경·대체·생략·추가)
```

- **세션 시작**: 추천 루틴(운동 목록, 운동별 무게·세트·횟수, 예상 시간)과 경고. 시작 전에 순서 변경·대체·생략 가능. `시작`으로 첫 운동 화면에 들어간다.
- **운동 화면**: 맨 위에 세션 진행 표시(`운동 3/5` + 다음 운동 이름). 그 아래 지금 운동 카드 하나(목표, 세트 목록, 입력/휴식 영역). 목표는 무게·횟수·세트를 칸으로 나눠 보여주고, 휴식 시간은 휴식 화면에서만 보인다. 추천 이유는 계획 화면에만 보인다. 카드 아래에 이 운동의 직전 기록을 접어서 둔다.
- **세션 목록 화면**: 진행 표시를 누르면 별도 화면으로 넘어간다 (시트가 아님). 맨 윗줄(`‹ 운동으로`, 제목, `편집`)은 스크롤해도 고정. 평소에는 운동마다 이름·상태(완료 / 진행 중 / 대기 / 생략)·목표 또는 기록한 세트만 보이고, 줄을 누르면 그 운동으로 이동. 목록을 열거나 편집을 켜고 끌 때 진행 중인 운동이 화면 가운데에 오도록 스크롤한다. `편집`을 누르면 줄마다 `대체`(같은 패턴 후보, §8), `생략`/`복원`, 순서 손잡이(≡)가 나타난다. 손잡이를 끌어 순서를 바꾸고, 화면 위·아래 끝으로 끌면 목록이 따라 스크롤된다. 계획 화면도 같은 손잡이로 순서를 바꾼다. 맨 아래에 `운동 추가`(균형 규칙에서 부족한 패턴을 먼저 제안, §5), `세션 종료`, `기록 버리고 처음으로`.
- **세션 요약**: 운동별 기록과 다음 세션 추천 미리보기. 여기서 저장 확정.
- **기록·진행 추이**: 세션 흐름과 분리된 별도 화면.
- **설정**: 바텀 시트. 운동 중 화면에는 운동에 필요한 것만.
- 라이트/다크 자동 대응(`prefers-color-scheme`), `prefers-reduced-motion` 대응.
- 색·타이포·간격은 별도 스타일 가이드에서 정의.

### 11.2 세트 입력 흐름 (운동 화면 안)

- **입력 모드와 휴식 모드를 번갈아 보여준다.** 둘이 동시에 보이지 않음.
  1. 입력 모드: 횟수 입력(§9.0, 탭으로 세기·`+N`으로 한 번에 더하기) → `세트 기록` → 체감 버튼(가벼움/적당/무거움, 건너뛰기 가능)
  2. 휴식 모드: 타이머(시작/리셋/+30초) → `다음 세트 시작` 또는 타이머 종료 시 자동 복귀
- **무게 탐색**(§4.4, 재기획 예정): 체감 버튼 결과로 다음 세트 무게를 제안. 확정 전 세트는 웜업으로 기록.
- **무게 단위**: 기구 단위(kg/lb) 그대로 입력하고 환산값을 같이 표시. 덤벨은 한 쪽 무게.
- **운동 끝내기와 세션 끝내기를 구분한다.**
  - `다음 운동으로`: 휴식 화면에 둔다. 목표 세트를 채우면 주 버튼이 되고, 휴식 타이머는 다음 운동 첫 세트 전 휴식으로 이어진다.
  - `세션 종료`: 마지막 운동의 휴식 화면과 세션 목록 화면에만 둔다. 세트 도중 실수로 누르지 않게.
  - `기록 버리고 처음으로`: 세션 목록 화면 맨 아래. 확인 후 진행 중 세션을 저장하지 않고 첫 화면으로 간다.
- 목표 세트 전에 다음 운동으로 넘어가도 된다. 남은 세트는 기록하지 않고 그 운동은 `완료`.
- 끝낸 운동으로 돌아가서 세트를 추가·수정할 수 있다. 세트는 세트 목록에서 눌러 수정·삭제.
- 진행 중인 세션은 `draft`로 따로 저장하고, 세션 요약에서 확정할 때 세션 기록으로 옮긴다.
- 기록이 있는 상태로 다시 열면 마지막으로 하던 운동의 휴식 화면(타이머 정지)으로 시작.

### 11.3 피드백

- 휴식 종료 시 비프 + 진동.
- **목표 대비 단계 표시**: 목표 미달 / 목표 도달 / +1~2 / +3 이상의 4단계 상태. 마지막 단계엔 움직임 강조.
- **급감 경고**: 같은 운동에서 직전 세트 대비 40% 이상 줄면 "여기서 마무리해도 좋아요".
- **추천·경고 표시**: 규칙 엔진의 `reason`은 계획 화면에만, `warnings`는 세션 시작 화면 배너에. 배너는 닫으면 같은 근거로는 다시 띄우지 않는다.
- 삭제·초기화·덮어쓰기·세션 종료 전에는 확인.

### 11.4 애니메이션

- 반복·세트 기록에 즉시 반응하고, 휴식에 들어가면 상태가 눈에 띄게 바뀐다.
- 애니메이션 영역을 눌러도 입력이 되게 (큰 터치 영역).
- 운동별 동작은 데이터로 정의해서 운동 추가가 쉽게.
- `prefers-reduced-motion`이면 움직임을 줄인다.
- 스타일은 미정 (§13).

### 11.5 데이터 저장

- 로컬 저장 + JSON 내보내기/가져오기.
- 저장 대상: 운동 카탈로그(§3), 세션 템플릿(§7), 확정된 세션 기록(§9.1), 진행 중 세션 `draft`, 사용자 정보(체중, 기구별 단위), `coach_notes`(§10.1), 설정.
- Google Sheets 연동은 선택. 실패해도 로컬 기록은 유지.

### 11.6 구현 시 주의할 점

- **iOS 오디오**: 사용자 제스처 안에서 만든 `AudioContext`만 소리가 난다 → 첫 탭에서 만들어 두고 재사용.
- **`[hidden]` 무력화**: 자체 `display`가 있는 요소는 브라우저 기본 `[hidden]`이 안 먹힌다 → `[hidden]{display:none}` 규칙을 따로 둘 것.
- **헤드리스 Chrome 캡처**: 창 폭이 최소 500px라 375px 확인은 iframe(`width:375px`)으로. `requestAnimationFrame` 애니메이션은 중간 프레임으로 찍힐 수 있음.
- **Apps Script 재배포**: `새 배포`는 URL이 바뀐다 → 배포 관리 → 편집 → `새 버전`으로.

### 11.7 화면 규칙

- **한 화면에 같은 정보는 한 번만.** 바꿀 수 있는 값은 보여주는 자리에서 바로 바꾼다 (무게·유산소 시간은 운동 카드의 −/+).
- **운동 중에는 지금 필요한 것만.** 휴식 시간은 휴식 화면에만, 추천 이유는 계획 화면에만.
- **표기는 하나로.** 무게 `37.5kg`, 세트 하나 `37.5kg × 8회`, 목표 `37.5kg × 8회 × 3세트`, 유산소 `15분`. 단위를 항상 붙인다. 운동 카드에서는 목표를 `무게 / 횟수 / 세트` 칸으로 나눈다. 보조 무게는 목록에서는 `보조 40kg`, 칸에서는 라벨을 `보조 무게`로.
- **세트 줄은 어디서나 같은 모양.** `1세트 | 37.5kg × 8회 | 체감`. 웜업은 번호 대신 `웜업`.
- **누를 수 있는 것은 테두리 있는 버튼이거나 끝에 `›`.** 글자만 있는 버튼은 화면·시트 머리에만 둔다 (왼쪽 `‹ 뒤로`, 오른쪽 설정·취소·닫기·편집·돌아가기).
- **화면과 시트의 구분.** 둘러보고 이동하는 곳은 화면, 하나를 고르거나 고치고 바로 돌아오는 일만 시트(세트 수정, 운동 대체·추가, 설정). 시트 머리(제목·`닫기`)는 스크롤해도 고정.
- **색의 뜻은 고정.** 파란 채움 = 그 화면의 주 행동 하나, 파란 테두리 = 지금 진행 중, 연파랑 배경 = 휴식, 회색 칸 = 값 표시. 카운터 테두리 색은 §11.3 단계 표시에만 쓴다.
- **상태는 이름 옆 작은 태그.** 진행 중 / 대기 / 완료 / 생략 / 선택 / 기록 없음.
- 입력 칸은 라벨 위, 칸 아래. 카드로 한 번 더 감싸지 않는다.

## 12. 구현 순서

### 1차 (MVP)
- **데이터**: 운동 카탈로그(§3.2의 등록 운동), 세션 기록과 `draft` 저장, JSON 내보내기/가져오기 (예시 파일 `workout_2026-11-07.json`을 가져올 수 있어야 함).
- **세션**: 상체(§7.1)·하체(§7.2) 템플릿으로 세션 시작 → 운동 화면 → 세션 요약. 세션 목록 화면에서 이동·순서 변경·생략·운동 추가(카탈로그에서 직접 선택).
- **입력**: `tap`/`batch` 전환(§9.0), 체감 버튼, 휴식 타이머와 비프·진동, 세트 수정·삭제, lb/kg 표시.
- **추천**: 더블 프로그레션(§4.1), 운동 카드에 `reason` 표시. 기록이 없는 운동은 추정 무게. `linear` 운동은 §4.3 규칙(웜업 세트 자동 생성 제외).

**1차 완료 기준**: 2026-11-07 세션(랫풀다운 먼저, 덤벨 프레스 웜업 2세트, 딥 생략, 리버스 펙덱 lb)을 앱에서 처음부터 끝까지 입력할 수 있고, 다음 세션 추천이 §4.1대로 나온다.

### 2차
- 네거티브 풀업 추천(§4.2)·선형(§4.3) 프로그레션, 풀업(§7.3)·하체(§7.2) 템플릿.
- 균형(§5)·회복(§6) 경고, 대체 추천(§8).
- 기록·진행 추이 화면.

### 3차
- 어시스턴트 대화(§10).
- Google Sheets 연동, 스타일 가이드와 애니메이션 적용.
