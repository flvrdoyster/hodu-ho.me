# 트레이닝 앱 명세

> 개인용 트레이닝 앱(hodu-home)의 단일 명세. §1–§9는 루틴 추천 규칙 엔진, §10은 어시스턴트 대화, §11은 UX, §12는 구현 순서, §13은 미정 항목, §14는 데이터 모델.
> 시각 요소(색·타이포·간격)는 별도 스타일 가이드에서 정의.
> 상체·하체·풀업처럼 성격이 다른 세션을 하나의 구조로 다루고, 운동과 세션 종류를 계속 추가할 수 있게 하는 것이 목표.
> 어시스턴트 대화(§10)는 이 문서와 최근 기록을 컨텍스트로 쓴다.

---

## 1. 핵심 개념

| 개념 | 설명 |
|---|---|
| **Exercise** | 개별 운동 (랫풀다운, 덤벨 프레스, 스쿼트 …). 카탈로그로 관리. |
| **Pattern** | 동작 유형 (수직 당기기, 수평 밀기, 힌지 …). 템플릿·대체·균형의 기준. 주동근·보조근과 연결 (§2). |
| **Session Template** | 세션 종류(상체/하체/풀업 …)별 **패턴 슬롯** 목록. 운동을 직접 고정하지 않음. |
| **Progression Model** | 운동별 증량 방식 (더블 프로그레션, 선형). |
| **Session Log** | 실제 수행 기록. 추천의 입력. (`workout_YYYY-MM-DD.json` 형식) |

**설계 원칙**: 템플릿은 "패턴 슬롯"으로 정의하고, 슬롯마다 들어갈 수 있는 운동은 카탈로그에서 고른다.
그래야 딥을 푸시다운으로, 풀업을 랫풀다운으로 바꾸는 것 같은 교체를 규칙으로 처리할 수 있고, 하체나 새 세션 종류를 추가해도 구조가 바뀌지 않는다.

## 2. 패턴과 근육

근육 관련 정의는 **쓰는 곳에 따라 세 층**으로 나눈다. 층마다 단위가 일정해야 한다.

| 층 | 단위 | 어디에 쓰나 |
|---|---|---|
| **pattern** | 동작 유형 (§2.1) | 템플릿 슬롯(§7), 대체 추천(§8), 균형 계산(§5) |
| **muscle** | 개별 근육, 한 가지 세밀도 (§2.2) | 회복 계산(§6). 패턴마다 주동근·보조근으로 연결 |
| **region** | 큰 신체 부위 (§2.3) | 화면 표시와 기록 필터만 ("오늘 쓴 부위"). 규칙 계산에는 쓰지 않음 |

### 2.1 패턴 → 주동근 / 보조근

| pattern | 설명 | 주동근 (primary) | 보조근 (secondary) |
|---|---|---|---|
| `vertical_pull` | 위→아래 당기기 | lats | biceps, middle_back, forearms |
| `horizontal_pull` | 앞→몸쪽 당기기 | middle_back, lats | biceps, rear_delts, traps |
| `horizontal_push` | 앞으로 밀기 | chest | front_delts, triceps |
| `vertical_push` | 위로 밀기 | front_delts | side_delts, triceps, traps |
| `rear_delt` | 후면 삼각근 고립 | rear_delts | middle_back, traps |
| `lateral_delt` | 측면 삼각근 고립 | side_delts | traps |
| `elbow_extension` | 삼두 고립 | triceps | — |
| `elbow_flexion` | 이두 고립 | biceps | forearms |
| `squat` | 무릎 주도 | quadriceps, glutes | adductors, hamstrings, lower_back |
| `hinge` | 고관절 주도 (데드리프트, RDL) | hamstrings, glutes | lower_back, traps, forearms |
| `lunge` | 한 발 하체 | quadriceps, glutes | hamstrings, adductors |
| `knee_extension` | 대퇴사두 고립 | quadriceps | — |
| `knee_flexion` | 햄스트링 고립 | hamstrings | calves |
| `calf` | 종아리 | calves | — |
| `core` | 코어 | abdominals | lower_back |
| `cardio` | 유산소 (사이클 등) | — | — (회복 계산 제외) |

- 운동이 패턴 기본값과 다르면 카탈로그에서 `muscles`로 덮어쓴다 (§3.1). 예: 클로즈그립 벤치는 triceps를 primary로.
- **균형 계산용 대분류**
  - 상체: `push` = horizontal_push, vertical_push, elbow_extension / `pull` = vertical_pull, horizontal_pull, rear_delt, elbow_flexion
  - 하체: `knee_dominant` = squat, lunge, knee_extension / `hip_dominant` = hinge, knee_flexion

[free-exercise-db](https://github.com/yuhonas/free-exercise-db)(퍼블릭 도메인)의 `primaryMuscles`/`secondaryMuscles` 어휘를 따른다. 공백은 `_`로 바꾼다.

`abdominals`, `abductors`, `adductors`, `biceps`, `calves`, `chest`, `forearms`, `glutes`, `hamstrings`, `lats`, `lower_back`, `middle_back`, `neck`, `quadriceps`, `traps`, `triceps`, 그리고 어깨 3개(아래).

- **바꾼 점 하나**: 원본의 `shoulders`는 `front_delts`, `side_delts`, `rear_delts`로 나눈다. 프레스(전면)와 리버스 펙덱(후면)은 회복이 겹치지 않아서, 하나로 묶으면 회복 경고가 틀어진다.
- 데이터셋에서 운동을 가져올 때는 `shoulders`를 운동에 맞는 쪽으로 바꿔 넣는다.

## 3. 운동 카탈로그

### 3.1 필드

```yaml
id: seated_cable_row
name: 시티드 케이블 로우
pattern: horizontal_pull
# muscles:                   # 선택. 없으면 패턴 기본값(§2.1)
#   primary: [middle_back, lats]
#   secondary: [biceps, rear_delts, traps]
equipment: cable_machine
load: weight                 # weight | assist | none (§14.6)
measure: reps                # reps | seconds
weight_basis: total          # total | per_side (덤벨). load가 none이면 없음
increment: 2.5               # 기본 증량 폭 (kg, 양수). load가 none이면 없음
rep_range: [8, 10]           # 더블 프로그레션 범위. measure가 reps일 때
# default_duration_sec: 900  # measure가 seconds일 때 기본 시간(초)
default_sets: 3
rest_sec: 90
progression: double          # double | linear | none
difficulty: 1                # 1 쉬움 ~ 3 기술 필요 (대체 추천 시 사용)
cue: 손으로 당기지 말고 팔꿈치를 내린다고 생각하세요   # 자세 한 줄(휴식 화면). 유산소·시간 운동은 없다
# unsupported: true          # 카탈로그에만 두고 선택 목록에서 숨김
```

- 카탈로그의 운동에는 **무게도 단위도 없다.** 기준 무게·추정 무게 필드도 없다. 무게는 오직 기록에서 나온다.
- 헬스장은 한 곳이라 기구 식별과 기구 등록은 없다. `equipment`는 분류 라벨일 뿐이고 세션 기록에 복사하지 않는다.
- **미측정**: 이 운동의 기록이 없는 상태. 기존 운동도 같다. 처음 할 때 시작 무게를 입력받는다 (§4.4).

### 3.1.1 데이터는 kg, 표시는 kg / lbs

- **데이터와 로직은 전부 kg**이다. 세션 기록의 무게(`weight_kg`), 추천, 증량, 같은 무게 비교, (앞으로 만들) 볼륨·근육 부하 모두 kg 숫자 하나만 다루고 로직에 단위 분기가 없다.
- **표시 단위**는 앱 설정 하나(`settings.weight_unit`: `kg` 기본 / `lbs`)다. 운동별로 저장하지 않는다. 운동 시트의 무게 줄, 운동 설정 시트, 세트 고치기 시트에 `kg ⇄ lbs` 버튼이 있고 누르면 바뀐다. 바꾸면 모든 무게 표기(세트 화면, 세트 줄, 계획·목록·요약, 추천 이유, 오늘 정리, 시트의 입력 칸)가 그 단위로 보인다.
- **lbs 표시**: 저장된 kg을 lbs로 환산해 **5lbs 단위로 반올림**해 보여준다(22.68kg → `50lbs`, 27.7kg → `60lbs`). 추천 무게도 같다. 스테퍼 −/+는 5lbs씩, 증량 폭 표기도 lbs(4.54kg → `10lbs`)다. 입력(시작 무게, 지금 무게, 증량 폭, 세트 수정)도 lbs로 받아 kg으로 환산해 저장한다. 세트를 기록할 때 저장하는 무게는 카드에 보인 값을 kg으로 환산한 값이다(보인 값과 저장값이 어긋나지 않게).
- **kg 표시**: 스테퍼는 그 운동의 kg 증량 폭으로 움직이고, 환산에서 온 값은 소수 첫째 자리로 보여준다(22.68 → `22.7kg`).
- 변환은 화면 경계의 함수 둘뿐이다: `Engine.kgToDisp`(kg→표시), `Engine.dispToKg`(표시→kg). 1lb = 0.45359237kg이고 환산값은 소수 둘째 자리로 저장한다(60lbs → 27.22kg). 입력 칸은 원래 값을 건드리지 않으면 저장값(kg)을 그대로 쓴다. 그래서 단위를 바꿔 보기만 해서는 데이터가 바뀌지 않는다.
- 같은 무게인가 하는 비교는 kg 허용 오차 0.1kg(`Engine.eq`)으로 한다.
- **운동별 증량 폭 덮어쓰기** `increments[운동 id]`: 카탈로그 기본값과 다른 운동만 kg 숫자로 저장한다(양수. 보조 운동도 양수). 추천·증량 계산이 이 값을 쓴다.
- lb 기구(리버스 펙덱, 레그 컬, 레그 익스텐션)의 기본 증량 폭은 10lbs에 해당하는 4.54kg이다.

## 4. 증량 규칙 (Progression)

### 4.1 더블 프로그레션 (`double`)

대부분의 머신·덤벨·케이블 운동에 적용. 본세트(`is_warmup: false`)만 계산한다. 기준 무게는 지난 세션의 본세트 가운데 **같은 무게(허용 오차 0.1kg)로 2세트 이상 한 무게들 중 가장 무거운 무게**다(보조 무게 운동은 가장 작은 보조 무게가 가장 무거운 것). 그런 무게가 없으면 가장 무거운 본세트 무게다. 횟수·체감·세트 수 판정은 그 무게로 한 본세트들만으로 한다. 2는 시간 맞추기의 운동당 최소 본세트 수와 같은 값(상수 `MIN_SETS`)이다. 마지막에 시험 삼아 무게를 올린 한 세트나 목표보다 가볍게 한 뒤 쪽 세트(예: 40 × 3세트 다음 30 × 1세트)가 기준을 바꾸지 않게 하려는 것이다. 목표 세트 수의 절반 같은 기준은 과거 기록에 목표 세트 수가 없어 쓰지 않는다.

```
min, max = rep_range
본세트 전부 reps >= max      → 다음 세션 weight + increment, 목표 reps = min
본세트 전부 reps >= min      → 무게 유지, 목표 reps +1 (max까지)
reps < min 인 세트가 2개 이상 → 무게 유지 (2회 연속이면 increment만큼 감량)
```

- 보조 운동(`load: assist`: 어시스트 딥, 어시스트 머신)은 "증량" = 보조를 `increment`만큼 줄이는 것이다. 무게는 0 아래로 내려가지 않는다.
- 증량 폭은 kg이고 운동별 설정(§3.1.1)을 쓴다.

### 4.2 보조 무게 운동 — 풀업·딥

- 어시스트 머신의 보조 무게로 관리하고, 증량은 더블 프로그레션(§4.1)을 따른다 (`load: assist` = 보조 감소).
- **완전 가동범위(턱이 바 위)만 유효 반복(`reps`)으로 센다.**
- 보조를 줄인 직후 rep_range 하한을 못 채우면 → 네거티브 풀업 3세트를 보조로 추천.

### 4.3 선형 (`linear`) — 데드리프트 등 주요 복합 운동

- 고정 반복(5회) × 4–5세트.
- 본세트 전부 5회 달성 + 자세 이상 없음 → +2.5kg.
- 5회를 못 채운 세트가 생기면 → 무게 유지. 2회 연속 실패 시 10% 감량 후 다시 올린다.
- 본세트 수가 목표 세트보다 적으면 증량하지 않는다 (더블 프로그레션도 같다).
- 웜업은 2세트 고정: 빈 봉(20kg) × 10, 작업 무게의 약 60~65% × 5.

### 4.4 시작 무게 (기준 무게 없는 운동)

별도의 탐색 절차는 없다. 기록이 없는 운동(기존 운동 포함)은 **시작 무게를 한 번 입력받는다** (§11.8).

- 입력한 무게가 첫 세션의 목표 무게다. 그 세션 기록부터는 일반 증량 규칙(§4.1·§4.3)을 따른다.
- 시작 무게는 진행 중 세션의 그 운동 항목에만 들어간다. 세션을 끝내지 않고 버리면 남지 않고, 기록이 생겨야 다음 추천이 나온다.

## 5. 균형 규칙

> 2차, 미구현. 지금은 상체 6번째 균형 슬롯(최근 7일 세트가 적은 패턴 고르기)만 있고, 아래 알림·`운동 추가` 우선 제안·경고 배너는 없다.

최근 **7일** 기준, 본세트 수로 계산.

| 체크 | 기준 | 알림 |
|---|---|---|
| push : pull | pull ≥ push (권장 1:1 ~ 1:1.5) | push가 pull보다 많으면 "당기기 추가 권장" |
| 수평 vs 수직 당기기 | 둘 다 1세트 이상 | 한쪽이 0이면 해당 패턴 추천 |
| 수평 vs 수직 밀기 | 둘 다 1세트 이상 | `vertical_push` 0이면 숄더 프레스 추천 |
| 팔 고립 | elbow_flexion, elbow_extension 각 1세트 이상 | 0인 쪽 추천 (낮은 우선순위) |
| 하체: squat vs hinge | 둘 다 1세트 이상 | 한쪽이 0이면 해당 패턴 추천 |
| 하체: knee_dominant vs hip_dominant | 세트 비율 1:1 근처 | 2배 이상 차이 나면 알림 |

## 7. 세션 템플릿 (패턴 슬롯)

슬롯 = `{pattern, priority, sets}`. `priority`: `core`(필수) / `main` / `optional`(시간 남을 때).
시간이 부족하면 optional → main 순으로 뺀다.

**슬롯의 운동 고르기**
- 슬롯의 후보(기본 운동 + 대체 후보) 중 **가장 오래 안 한 운동**을 고른다. 기록이 없는 후보가 가장 오래된 것으로 친다. 날짜가 같으면 기본 운동이 앞선다.
- 기록이 없는 운동(미측정)은 한 세션에 하나까지만 자동으로 넣는다. 그 뒤 슬롯은 기록이 있는 후보 중에서 고른다. 시간 운동(유산소)은 미측정이 아니므로 이 개수에 세지 않는다.
- 한 세션에 같은 운동이 두 번 들어가지 않는다.
- 유산소 슬롯(슬롯 정의에 `recent: true`)은 돌려 쓰지 않는다. 후보 중 **가장 최근에 한 종목**을 고르고, 기록이 있는 후보가 없으면 기본(`stationary_bike`)이다. 날짜가 같으면 후보 순서(기본이 먼저)가 앞선다. 유산소 후보는 `stationary_bike`, `running`, `treadmill`, `stair_climber`이고, 대체 시트에는 같은 `cardio` 패턴이라 후보로 나온다. 목표 시간은 고른 종목의 지난 기록(없으면 기본 시간)이다.
- 후보가 하나뿐인 슬롯과 균형 슬롯(상체 6번째)은 각자 규칙대로다. 균형 슬롯은 최근 7일 세트가 적은 패턴을 고른다.

**운동 시간에 맞춰 세션 짜기**
- 운동 시간은 세션마다 정한다. 계획 화면과 세션 목록 화면 맨 위의 `운동 시간` 칸에서 −/+ 5분 (누르면 직접 입력). 마지막으로 쓴 값이 다음 세션의 기본값이다 (처음은 35분). 범위는 10~60분이다(상수 `TIME_MIN`·`TIME_MAX`). 한계에 닿으면 −/+가 꺼지고, 직접 입력한 값이 범위를 벗어나면 가장 가까운 한계로 맞춘 뒤 토스트로 알린다. 저장된 설정이나 진행 중 세션의 값이 범위를 벗어나 있으면 불러올 때 범위 안으로 맞춘다. 유산소는 이 시간에 넣지 않는다.
- 예상 시간 = 운동마다 `(본세트 + 예상 웜업) × 세트 시간`. 예상 웜업은 `linear` 운동은 2세트 고정(§4.3), 나머지는 직전 3번의 그 운동 기록에 있던 웜업 세트 수의 평균을 반올림한 값이고 기록이 없으면 0이다(무게 없는 운동·시간 운동은 0). 진행 중인 운동은 예상 웜업에서 이미 기록한 웜업을 뺀 만큼만 남고(0 미만은 0), 본세트를 하나라도 기록했으면 남은 웜업은 0이다. 세트 시간은 그 운동의 세트 기록 시각 사이 간격 평균이며 웜업 세트의 기록 시각도 포함한다. 지금 세션과 직전 3번의 그 운동 기록에서 모으고, 10분이 넘는 간격은 뺀다. 기록 시각이 없으면 `휴식 + 40초`. 운동 사이 이동 시간은 넣지 않는다. 경과 시간은 `시작`을 누른 때부터 잰다. 마지막 기록(세트 또는 시간 운동 기록) 뒤 10분이 지나면 경과 시간은 더 늘지 않는다(표시만, 세션은 자동 종료하지 않는다). 기록이 아직 없으면 `시작` 뒤 10분이 상한이다.
- **방치된 세션 자동 종료**: 마지막 기록 뒤 30분(상수 `IDLE_END_MS`) 동안 기록이 없으면 세션을 자동으로 끝내 저장한다. 저장은 `세션 종료` 후 저장과 같은 경로이고 `duration_sec`은 시작~마지막 기록이다. 기록한 세트가 하나도 없거나(기록한 운동을 모두 생략해 저장할 운동이 없는 경우 포함) 저장할 운동이 없으면 `시작` 뒤 30분에 저장 없이 진행 중 세션만 지운다. 앱 안에서는 주기적으로, 앱을 다시 열 때와 화면이 다시 보일 때(`visibilitychange`)도 검사한다. 끝나면 홈 화면으로 가고 토스트로 `30분 동안 기록이 없어 세션을 자동으로 저장했어요`(기록이 없으면 `기록이 없어 진행 중이던 세션을 지웠어요`)를 알린다. 체중·메모는 초안에 입력된 것만 저장된다(설정 체중은 넣지 않는다). 요약 화면에서 직접 저장하면 화면에 보이는 설정 체중이 들어간다.
- 2026-11-14 상체 기록 기준: 랫풀다운 102초, 덤벨 프레스 148초, 시티드 로우 121초, 푸시다운 79초, 리버스 펙덱 86초 (예전 고정값 100~160초). 이 다섯 운동의 본세트만 센 예상 합은 28.5분, 웜업을 넣으면 31.0분(덤벨 프레스 예상 웜업 1), 실제 첫 세트~마지막 세트는 약 28분. 같은 방식으로 2026-11-15 하체(데드리프트·레그 프레스)는 17.0분 → 23.4분, 실제 약 18분.
- 시간을 바꾸거나 운동을 추가·대체·생략·복원하면 세션을 다시 짠다. 자동으로 뺐던 운동과 줄였던 세트를 되돌린 뒤, `경과 + 남은 예상`이 운동 시간을 넘는 만큼 아래 순서로 줄인다.
  1. 아직 시작하지 않은 optional 운동을 뒤에서부터 뺀다.
  2. 같은 방식으로 main 운동을 뺀다.
  3. 그래도 넘으면 남은 운동의 본세트를 뒤에서부터 하나씩, 운동당 최소 2본세트까지 줄인다. 웜업은 줄이지 않고, 운동을 통째로 뺄 때만 같이 빠진다.
- 세트를 기록할 때마다 같은 계산을 다시 해서 넘는 만큼 더 줄인다 (되돌리기는 하지 않는다). 줄인 내용은 휴식 화면에 알린다.
- 진행 중이거나 기록이 있는 운동, 직접 복원한 운동은 빼지 않는다. 직접 생략한 운동은 자동으로 되살리지 않는다.
- 운동 시간이 되면 휴식 화면에 안내를 띄우고 `세션 종료`를 주 버튼으로 둔다. 휴식 도중에 시간이 되면 탭하지 않아도 그 순간 한 번 다시 그려 바꾼다.

**시간 띠(세션 막대)**
- 운동 시간 전체를 가로 띠 하나로 그린다. 운동마다 예상 시간만큼의 칸을 차지하고, 남는 시간은 점선 칸으로 둔다.
- 운동 칸의 폭은 웜업을 포함한 예상 시간이다. 채움은 `(기록한 웜업 + 기록한 본세트) / (예상 웜업 + 목표 본세트)`이다. 본세트를 기록한 뒤에는 남은 웜업이 없으므로 예상 웜업 자리에 기록한 웜업 수를 쓴다.
- 세로 눈금은 경과 시간이다. 채워진 끝보다 눈금이 앞서 있으면 계획보다 늦은 것. 운동 시간을 넘기면 오른쪽 `경과 / 운동 시간` 글자가 강조색이 된다.
- 계획 화면과 세션 목록 화면에 그리고, 운동·휴식 화면 위쪽에도 둔다. 오른쪽에 `경과 / 운동 시간`(분)이 있다. 계획 화면의 운동 줄 `약 N분`과 줄 시트의 예상 시간은 웜업을 포함한 같은 값이다.

### 7.1 상체 (`upper`, 30–40분)

| 순서 | pattern | priority | 기본 운동 | 대체 후보 |
|---|---|---|---|---|
| 1 | vertical_pull | core | assisted_pullup | lat_pulldown |
| 2 | horizontal_push | core | dumbbell_press | bench_press, assisted_dip |
| 3 | horizontal_pull | core | seated_cable_row | dumbbell_row |
| 4 | elbow_extension | main | cable_pushdown | assisted_dip |
| 5 | rear_delt / lateral_delt | main | reverse_pec_deck | lateral_raise_machine, cable_lateral_raise |
| 6 | vertical_push / elbow_flexion | optional | (균형 규칙 결과로 선택) | dumbbell_shoulder_press, dumbbell_curl |
| + | cardio | optional | stationary_bike 15분 | — |

- 순서 재배치 규칙: primary 근육이 겹치는 슬롯이 연달아 오지 않게 push/pull을 번갈아 배치.

### 7.2 하체 (`lower`, 30–40분) — 초안

| 순서 | pattern | priority | 기본 운동 | 대체 후보 |
|---|---|---|---|---|
| 1 | hinge 또는 squat (번갈아) | core | deadlift | romanian_deadlift / squat, leg_press |
| 2 | 1번과 반대 패턴 | core | leg_press | squat, hack_squat |
| 3 | knee_flexion | main | leg_curl | — |
| 4 | lunge 또는 knee_extension | main | leg_extension | split_squat, walking_lunge |
| 5 | calf / core | optional | calf_raise | plank, cable_crunch |
| + | cardio | optional | stationary_bike 15분 | — |

- 데드리프트가 있는 날은 1번을 hinge로 고정하고, 2번은 무릎 주도 운동.
- 앱의 기본 구성은 deadlift → leg_press → leg_curl → leg_extension → stationary_bike. 대체 후보(romanian_deadlift, squat, hack_squat, split_squat, walking_lunge)는 카탈로그에 있고 대체·추가 시트에서 고른다. 5번(calf / core) 기본 슬롯은 아직 넣지 않았다.

### 7.3 풀업 (`pullup`, 홈)

| 순서 | pattern | priority | 운동 |
|---|---|---|---|
| 1 | — | core | 데드행 30초 (웜업) |
| 2 | vertical_pull | core | assisted_pullup 3 × 6–8 |
| 3 | vertical_pull | optional | 네거티브 풀업 3세트 (보조 무게 하향 직후) |

### 7.3.1 자유 (`free`)

상체·하체와 나란한 세 번째 세션 종류다. 템플릿은 `{ name: '자유', free: true, slots: [] }`이고 `session_type`은 `"free"`다.

- **시작은 빈 목록.** 계획 생성(`buildSession`)은 슬롯이 없어 빈 배열을 돌려준다. 운동은 전체 카탈로그에서 `운동 추가`로 넣는다(상·하체 구분 없음). 시작한 뒤에도 같은 방식으로 더한다.
- **시간 계획.** 예상 시간(운동별·세션 합계)과 시간 띠는 다른 세션과 똑같이 계산해 보여 준다. 시간 상한에 따른 자동 세트 축소와 자동 생략은 하지 않는다(`fitToTime`이 free에서는 아무것도 바꾸지 않는다). 운동 시간이 지나면 보이는 안내는 그대로 나온다.
- **계획 화면.** 제목은 `자유 세션 · 날짜`. 운동이 하나도 없으면 줄 자리에 `운동을 추가해서 시작하세요`를 보이고, 맨 아래 주 버튼은 `운동 추가`이며 `시작`은 두지 않는다(운동이 생기면 다른 세션처럼 `운동 추가`는 조용한 글자 버튼, `시작`이 주 버튼). 예상 합계가 운동 시간을 넘으면 줄이지 않고 시간 띠 오른쪽 글자를 시간 색으로 바꾸며 띠 아래에 `목표를 N분 넘었어요`를 보인다. `시간에 맞춰 뺀 운동` 줄은 나오지 않고 `지난 세션 메모`는 보이지 않는다(같은 종류의 지난 세션 메모가 의미 없는 구성이라).
- **추천은 세션 종류와 무관하다.** 운동별 추천(무게·횟수)은 그 운동의 기록 전체에서 계산하므로, 자유 세션에서 한 기록은 상·하체 세션의 같은 운동 추천에 반영되고 그 반대도 같다. 균형 규칙의 최근 7일 패턴별 세트 수, `recent` 슬롯의 최근 운동, 회복 규칙도 모든 세션 종류를 합쳐 센다.
- **슬롯이 없다.** 자유 세션의 항목은 `slot`이 비고 `priority`는 `main`이다. 대체 후보는 같은 패턴 운동만 쓰고 슬롯 후보는 더하지 않는다.
- **상체·하체 번갈이.** 앱은 다음 세션 종류를 자동으로 고르지 않고 사용자가 직접 누른다. 앞으로 번갈이 제안을 넣는다면 **자유 세션은 번갈이 계산에서 뺀다**(마지막 `upper`/`lower` 세션만 보고 반대쪽을 제안). 자유 세션은 운동 구성이 정해져 있지 않아 어느 쪽을 했다고 볼 수 없기 때문이다.
- **기록과 데이터.** 저장 모양은 다른 세션과 같고 버전도 그대로 3이다(`session_type`은 임의 문자열이고 `free`는 값이 하나 늘 뿐이다). 내보내기·가져오기·`records/`는 종류를 가리지 않으며, 파일 이름은 `날짜-free.json`이다. 같은 세션 판정(§14.10)은 종류가 같을 때만 비교하므로 같은 날 상체와 자유 세션은 따로 둔다. 기록 목록과 요약은 종류를 `tplName`(자유)으로 보여 준다.

### 7.4 새 세션 종류 추가

템플릿 파일에 슬롯 목록만 추가하면 된다 (예: `full_body`, `push`, `pull`). 증량·균형·회복 규칙은 그대로 적용.

## 8. 대체 규칙

사용자가 운동을 건너뛰거나 "어렵다"고 할 때.

1. 같은 `pattern` 안에서 `difficulty`가 더 낮은 운동으로 대체.
2. 같은 pattern 후보가 없으면 primary 근육이 겹치는 고립 운동으로 대체 (예: 딥 → 푸시다운. 딥은 카탈로그에서 `muscles.primary`에 chest, triceps를 둔다).
3. 생략 시 균형 규칙에서 해당 패턴이 부족해지면 다음 세션에서 우선 추천.

## 9. 입출력

### 9.0 횟수 입력 방식

한 회씩 세지 않는다. 세트 화면의 횟수는 세트가 시작될 때 목표 횟수로 채워져 있다.

- 목표대로 했으면 `N회 했어요` 버튼 한 번으로 세트가 기록된다.
- 횟수가 달랐으면 버튼 양옆 `−` `+`로 1씩 맞춘다(최소 1). 숫자와 버튼 문구가 같이 바뀐다.
- 세트를 기록하거나 운동을 옮기거나 운동을 대체하면 횟수를 다시 목표로 채운다.
- 시간 운동도 같은 방식이다. 목표 분으로 채워져 있고 `−` `+`는 1분, 숫자를 누르면 직접 입력한다. 직접 입력은 1~240분(`duration_sec` 60~14400)으로 맞추고, 벗어나면 가장 가까운 한계로 맞춘 뒤 토스트로 알린다.
- 제대로 수행했는지는 운동하는 사람이 판단한다. 제대로 하지 못한 반복은 세지 않고, 부분 반복을 따로 기록하지 않는다.

**세트 체감 입력 (`feel`)**: 휴식 화면의 `방금 N세트` 카드에 `가벼움 / 적당 / 무거움` 3택이 있다. 고르지 않아도 넘어갈 수 있고, 고른 것을 다시 누르면 지워진다. 세트 고치기 시트에서도 바꾼다.
- 더블 프로그레션(§4.1)과 `linear`(§4.3) 모두, 목표를 채웠더라도 `무거움`이면 증량을 한 세션 미룬다.

### 9.1 입력: 세션 기록

세션 기록의 형식은 §14.4가 정한다. 추천에 쓰는 것은 세트의 `weight_kg`, `reps`, `duration_sec`, `is_warmup`, `feel`, `at`뿐이다. 예전 형식의 파일은 불러올 때 §14.8로 변환한다.

### 9.2 출력: 다음 세션 추천

```json
{
  "session_type": "upper",
  "date": "2026-11-09",
  "estimated_min": 38,
  "items": [
    {
      "slot": 1,
      "exercise_id": "lat_pulldown",
      "weight_kg": 37.5,
      "sets": 3, "reps": 8,
      "reason": "지난 세션 35kg × 10 × 3 전부 상한 달성 → +2.5kg"
    }
  ],
  "warnings": ["최근 7일 vertical_push 0세트 → 숄더 프레스 추천"]
}
```

- `reason`은 항상 채운다 (어떤 규칙이 적용됐는지). 어시스턴트(§10)가 이걸 근거로 설명·수정한다.

## 10. 어시스턴트 대화

운동 중에 앱 안에서 Claude와 대화하며 루틴을 조정한다. ("랫풀다운 먼저 했어", "딥 어려워", "하나 더 넣어줘", "파운드로 돼 있는데" 같은 요청)

### 10.1 연결 방식

- claude.ai의 채팅 세션은 외부 앱에서 이어 쓸 수 없다. 앱이 **Claude API(Messages API)를 직접 호출**하고, 대화 기록은 앱이 저장한다.
- **대화 스레드 = 운동 세션 하나.** 세션 시작 때 새 스레드를 열고, 세션 `draft`와 같이 저장한다. 앱을 닫았다 열어도 이어진다.
- **세션 사이의 연속성은 코치 노트로.** 세션 종료 때 Claude가 그 대화를 짧게 요약해 `coach_notes`에 추가한다 (예: "딥은 아직 어려워함, 푸시다운으로 대체", "로우 30kg이 적정"). 다음 세션의 시스템 프롬프트에 넣는다. 사용자가 노트를 직접 보고 고칠 수 있게 한다.
- 모델: 운동 중 대화는 응답 속도가 중요하므로 Sonnet급. 세션 요약은 같은 모델이나 더 가벼운 모델.
- API 키: 레포가 공개이므로 키를 코드에 넣지 않는다. 설정 화면에서 입력해 기기에만 저장하거나, 작은 서버리스 프록시를 둔다.

### 10.2 컨텍스트

| 위치 | 내용 | 갱신 |
|---|---|---|
| 시스템 프롬프트 | 역할(트레이닝 코치), 이 명세의 §1–§9, 사용자 기본 정보(체중, 운동별 증량 폭), `coach_notes` | 세션 시작 때 |
| 매 요청에 첨부 | **현재 세션 상태 JSON**: 운동 목록과 상태, 기록된 세트, 지금 운동, 입력/휴식 모드, 경과 시간 | 매 요청 |
| 세션 시작 때 1회 | 최근 2~4주 세션 기록, 규칙 엔진 추천(§9.2) | 세션 시작 때 |
| 대화 기록 | 이 세션의 사용자·Claude 메시지 | 누적 |

세션 상태를 매번 붙이므로, 사용자가 "2세트 끝"처럼 짧게 말해도 Claude가 어느 운동 몇 세트째인지 안다.

### 10.3 도구 (앱 조작)

Claude는 답만 하지 않고 **도구 호출로 앱 상태를 바꾼다.** 예: "12kg이 적당한 듯" → 남은 세트 목표를 12kg으로 수정.

| 도구 | 하는 일 |
|---|---|
| `set_target` | 운동의 목표 무게·횟수·세트·휴식 수정 (지금 운동 또는 남은 세트만) |
| `swap_exercise` | 운동 대체 (§8 후보 안에서 우선) |
| `add_exercise` | 운동 추가 (위치 지정) |
| `skip_exercise` | 운동 생략 |
| `reorder` | 운동 순서 변경 |
| `log_set` | 세트 기록 (사용자가 말로 알려준 경우: "30kg 10회 했어") |
| `edit_set` | 기록된 세트 수정 |
| `add_note` | 운동이나 세션에 메모 |
| `get_history` | 특정 운동의 과거 기록 조회 |

- 도구가 바꾼 내용은 대화 아래에 **변경 칩**으로 보여주고 탭 한 번으로 되돌릴 수 있게 한다. 확인 없이 바로 적용한다 (운동 중에는 확인 단계가 번거롭다).
- 무게는 규칙 엔진 값을 기본으로 하고, Claude가 바꿀 때는 이유를 같이 남긴다 (§9.2의 `reason`과 같은 형식).

### 10.4 화면

- 운동 화면 어디서든 열 수 있는 **대화 시트**. 입력/휴식 영역을 가리지 않도록 반쯤 올라오는 시트.
- 답변은 짧게. 무게·횟수·세트를 항상 숫자로 명시 (운동 중에 바로 따라 할 수 있게).
- 텍스트 입력 외에 **음성 입력**을 고려 (§13).

### 10.5 규칙 엔진과의 관계

- 규칙 엔진(§4–§8)은 그대로 기본값을 만든다. 어시스턴트는 그 결과를 상황에 맞게 조정하는 역할.
- 어시스턴트가 바꾼 값도 세션 기록에 남으므로, 다음 세션의 규칙 엔진 계산에 그대로 반영된다.

---

### 10.6 서버 없는 코치 (현재 구현)

§10.1~10.5의 대화형 어시스턴트는 서버가 필요해 미구현. 그 전 단계로 앱 안의 기록만으로 아래를 한다. 여기서 쌓는 메모는 나중에 어시스턴트의 컨텍스트로 쓴다.

- **메모 적기**: 세트 메모는 세트 고치기 시트에서, 운동 메모는 운동 시트의 `메모` 줄에서 적는다. 세션 메모는 세션 요약의 `메모 추가`에서. 세트 메모는 운동 시트의 세트 줄 아래에 보인다.
- **지난 메모 보여주기**: 운동 시트에 그 운동의 직전 세션 메모와, 그 운동 기록에 적어 둔 다음 목표(`next_note`)를 보여준다. 계획 화면에는 같은 종류 직전 세션의 세션 메모와 `watch_note`를 보여준다.
- **오늘 정리** (세션 요약 맨 위, 규칙으로 뽑는다)
  - 근력에 쓴 시간과 운동 시간 (마지막 근력 세트 기록 시각 − 시작 시각)
  - 본세트 수: 한 것 / 계획 (시간 때문에 자동으로 뺀 운동 포함)
  - 다음에 무게를 올리는 운동, 무거워서 증량을 미루는 운동, 횟수를 못 채워 유지하는 운동, 두 번 연속 못 채워 내리는 운동 (§4.1·§4.3 판정)
  - 시간에 맞춰 뺀 운동, 세트를 덜 한 운동
- 세트 기록에 기록 시각 `at`(ISO)을 남긴다.

## 11. UX

### 11.1 화면 구조

하루 세션은 여러 운동으로 이루어진다. **운동 화면에는 지금 하는 운동 하나만** 보여주고, 운동 사이를 오간다.

```
세션 시작 ──▶ 운동 화면 (운동 1) ──▶ 운동 화면 (운동 2) ──▶ … ──▶ 세션 요약
                 ▲      │
                 └ 세션 목록 화면 (이동·순서 변경·대체·생략·추가)
```

- **세션 시작**: 추천 루틴(운동 목록, 운동별 무게·세트·횟수, 예상 시간)과 경고(경고는 2차, 미구현). `운동 시간` −/+(5분, 숫자를 누르면 직접 입력)와 시간 띠가 맨 위에 있다. 줄에는 목표와 추천 결론(`목표 +1회`, `무게 유지`, `+2.5kg`)만 보이고(무게가 그대로이고 다른 결론이 있으면 `무게 유지,` 접두어는 뺀다), 줄을 누르면 **줄 시트**가 열려 오늘 목표·예상 시간·추천 이유 전문과 `다른 운동으로 대체`·`오늘은 생략`(생략된 운동은 `복원`)이 나온다. 시간에 맞춰 뺀 운동은 한 줄(`시간에 맞춰 뺀 운동 N개`)로 접히고 누르면 **뺀 운동 시트**에서 하나씩 `복원`한다. 줄 오른쪽 끝에는 순서 손잡이(≡)가 항상 있고, 손잡이에서 시작한 끌기만 순서를 바꾼다(줄 누름은 줄 시트, 줄 몸통의 세로 끌기는 스크롤). 순서는 줄에 보이는 운동 사이에서 바뀌고, 접힌 뺀 운동은 제자리에 둔다. `운동 추가`, `시작`.
- **운동 화면**: 위에서부터 머리(`상체 · 2 / 4번째 운동`과 오른쪽 `목록`), 시간 띠, 운동 이름(누르면 **운동 시트**), 그 아래가 입력 화면 또는 휴식 화면이다. 입력 화면은 세트 번호(`2세트 / 3`), 무게, 횟수, `지난번` 한 줄, 맨 아래 `−` `N회 했어요` `+`. 휴식 화면은 `방금 N세트` 카드(무게 × 횟수, 체감 3택, `고치기`), 남은 휴식 시간과 `일시정지`·`리셋`·`+30초`, `다음` 안내, 맨 아래 버튼이다. 세트 목록·메모·직전 기록은 운동 시트에 있고 운동 화면에 늘어놓지 않는다. 휴식 시간은 휴식 화면에서만, 추천 이유 전문은 줄 시트에서만 보인다. 무게를 누르면 운동 시트가 열린다.
- **홈 화면**: 머리에는 제목 없이 오른쪽 `설정`만 둔다. 그 아래 목록 머리 `운동 기록`과 최근 세션 2개를 최신이 위로, 조용한 한 줄씩 보인다(`오늘 · 상체 · 35분`, `어제 · 하체 · 18분`, `3일 전 · 상체 · 35분`). 날짜는 기기 로컬 날짜 기준 달력상 차이로 세며(0일 오늘, 1일 어제, 그 이상 N일 전, 상한 없음), 미래 날짜는 원래 날짜(`2026-11-25`)를 보인다. 종류(상체·하체·자유)와 걸린 시간만 있고 누르는 동작은 없다. 기록이 1개면 1개만, 없으면 목록 머리 아래에 `아직 기록이 없어요.`. 그 아래 발판에 `상체`·`하체`·`자유` 세션 버튼.
- **세션 목록 화면**: 머리의 `목록` 버튼을 누르면 별도 화면으로 넘어간다 (시트가 아님). 머리(뒤로 가기 아이콘, 제목, `편집`)는 스크롤해도 고정. 운동마다 이름·목표 또는 기록한 세트·오른쪽 끝 상태(완료 / 진행 중 / 대기 / 생략)가 보이고, 줄을 누르면 그 운동으로 이동(생략된 줄은 줄 시트에서 `복원`). 목록을 열거나 편집을 켜고 끌 때 진행 중인 운동이 화면 가운데에 오도록 스크롤한다. 위쪽 시간 띠 오른쪽의 `경과 / 운동 시간` 글자를 누르면 운동 시간을 직접 입력한다. `편집`을 누르면 줄마다 순서 손잡이(≡)가 나타나 끌어 순서를 바꾸고(화면 위·아래 끝으로 끌면 목록이 따라 스크롤), 줄을 누르면 줄 시트가 열려 대체·생략을 한다. 맨 아래에는 조용한 글자 버튼 `운동 추가`(2차, 미구현: 균형 규칙에서 부족한 패턴을 먼저 제안, §5. 지금은 패턴별 전체 목록)·`세션 종료`·`기록 버리고 처음으로`가 한 줄로 놓이고, 그 아래 주 버튼은 편집 중이 아닐 때만 `지금 운동으로`(진행 중인 운동 화면으로 간다)이고, 편집 중에는 주 버튼을 두지 않는다(편집은 머리 오른쪽의 `편집`/`완료`로 켜고 끈다. 같은 일을 하는 버튼이 둘이 되지 않게).
- **세션 요약**: 걸린 시간, 오늘 정리, 운동별 기록과 다음 세션 추천 미리보기. 체중은 `체중` 버튼(누르면 직접 입력), 메모는 `메모 추가` 버튼(메모 시트)으로 넣고 초안에 바로 저장된다. `저장`으로 확정.
- **기록·진행 추이**: 세션 흐름과 분리된 별도 화면.
- **설정**: 바텀 시트. 운동 중 화면에는 운동에 필요한 것만.
- 라이트 색만 쓴다(다크 모드 없음). `prefers-reduced-motion`이면 움직임을 줄인다.
- 색·타이포·간격은 `STYLE-GUIDE.md`에서 정의.

### 11.2 세트 입력 흐름 (운동 화면 안)

- **입력 모드와 휴식 모드를 번갈아 보여준다.** 둘이 동시에 보이지 않음.
  1. 입력 모드: 횟수 확인(§9.0, 목표로 채워진 값을 −/+로 맞추기) → `N회 했어요`. 체감은 이어지는 휴식 화면에서 고른다(건너뛰기 가능).
  - 시간 운동(유산소)은 휴식 모드 없이 입력 화면만 있다. `N분 했어요`를 누른 때의 값만 기록된다. 기록한 뒤에는 `기록 N분`이 따로 보이고, −/+로 입력 값을 바꿔도 `N분으로 다시 기록`을 눌러야 기록이 바뀐다(값이 같으면 버튼이 꺼진다). 저장·요약·다음 추천은 기록된 값을 쓴다.
  2. 휴식 모드: 타이머(시작/리셋/+30초) → `다음 세트 시작` 또는 타이머 종료 시 자동 복귀
- **자세 한 줄**: 휴식 화면에서 다음 세트를 안내하는 줄(`다음 · N세트 · 무게 × 횟수`) 아래에 그 운동의 `cue`를 한 줄 보인다. 다음이 다른 운동이거나 운동 시간이 다 된 때, `cue`가 없는 운동(유산소·시간)은 보이지 않는다. 입력 화면·계획·목록·요약에는 넣지 않고 세션 기록에도 저장하지 않는다. 운동당 하나로 고정이다. 문구 기준: 수행 방법 설명이 아니라, 염두에 둘 흔한 실수 하나 또는 효과를 높이는 팁 하나. 앱의 다른 안내와 같은 해요체. 포인트를 여러 개 넣지 않고 과장·의학적 단정·부상 조언은 쓰지 않는다.
- **웜업 자동 인식**: 세트를 기록할 때 그 무게가 운동의 목표 무게(계획 때의 무게, `운동 설정`에서 고친 무게)보다 증량 폭 한 칸을 넘게 가볍고, 그 운동에서 목표 무게에 가까운 세트나 본세트를 아직 기록하지 않았다면 웜업으로 기록한다. 운동 시트의 −/+로 바꾼 무게는 목표 무게로 치지 않는다. 목표 무게 가까이 한 번이라도 기록한 뒤에는 더 가벼운 세트도 본세트다. 보조 무게 운동, 무게 없는 운동, 시간 운동은 자동 인식하지 않는다. 웜업은 세트 번호 자리에 `웜업`으로 보이고, 본세트 번호·목표 세트 대비 진행·증량 판정·오늘 정리는 웜업을 뺀 본세트로 센다. 남은 예상 시간과 시간 띠는 웜업을 따로 예상해 함께 센다(§7 운동 시간에 맞춰 세션 짜기). 같은 무게로 목표보다 가볍게 이어 하면(허용 오차 0.1kg, 예: 목표 40에서 30 × 2세트) 두 번째 세트를 기록할 때 그 무게로 자동 판정된 앞 세트의 웜업을 풀어 모두 본세트로 한다. 무게를 올려 가는 웜업(20 → 30 → 40)은 그대로 웜업이다. 세트 고치기 시트의 `웜업 세트` 스위치로 바꿀 수 있고, 바꾼 세트는 이후에도 다시 뒤집지 않는다. `운동 설정`을 저장해도 목표 무게 칸을 직접 고치지 않았다면 목표 무게는 그대로다.
- **입력 범위**: 화면에서 직접 입력하는 숫자는 범위로 맞춘다. 무게 0~1000kg(보조 무게 운동도 0 이상), 횟수 1~200, 체중 20~300kg, 증량 폭 100kg 이하, 시간 운동 1~240분. 벗어나면 가장 가까운 한계로 맞춘 뒤 `무게를 1000kg으로 맞췄어요` 같은 토스트로 알린다(무게는 보이는 단위로 쓴다). 무게 −/+ 버튼도 같은 한계를 넘지 않는다. 숫자가 아니면 `~를 확인해 주세요`.
- **무게 단위**: 데이터는 kg, 화면은 kg / lbs 전환(§3.1.1). 덤벨은 한 쪽 무게. 증량 폭은 `운동 설정` 시트(§11.8)에서 바꾼다. 운동 시트의 무게 `−` `+`는 증량 폭만큼 움직인다(lbs는 5).
- **운동 끝내기와 세션 끝내기를 구분한다.**
  - `다음 운동으로`: 휴식 화면에 둔다. 목표 세트를 채우면 주 버튼이 되고, 휴식 타이머는 다음 운동 첫 세트 전 휴식으로 이어진다.
  - `세션 종료`: 마지막 운동의 휴식 화면, 운동 시간이 다 됐을 때의 휴식 화면, 세션 목록 화면에만 둔다. 세트 도중 실수로 누르지 않게. 세션 목록 화면에서는 조용한 글자 버튼이다(주 버튼은 편집 중이 아닐 때 `지금 운동으로`).
  - `기록 버리고 처음으로`: 세션 목록 화면 맨 아래의 조용한 글자 버튼. 확인 후 진행 중 세션을 저장하지 않고 첫 화면으로 간다.
- 기록한 세트(시간 운동 포함)가 하나도 없으면 `세션 종료`는 요약 대신 확인을 거쳐 진행 중 세션을 저장 없이 지우고 첫 화면으로 간다(`기록이 없어 진행 중이던 세션을 지웠어요`). 빈 세션은 저장하지 않는다.
- 화면의 주 버튼이 다른 동작으로 바뀐 직후 400ms 동안은 하단 버튼 누름을 무시한다(연타로 다음 버튼을 잘못 누르지 않게).
- 목표 세트 전에 다음 운동으로 넘어가도 된다. 남은 세트는 기록하지 않고 그 운동은 `완료`.
- 끝낸 운동으로 돌아가서 세트를 추가·수정할 수 있다. 세트는 운동 시트의 `오늘` 줄이나 휴식 화면의 `고치기`로 눌러 수정·삭제.
- 진행 중인 세션은 `draft`로 따로 저장하고, 세션 요약에서 확정할 때 세션 기록으로 옮긴다.
- 기록이 있는 상태로 다시 열면 마지막으로 하던 운동의 휴식 화면(타이머 정지)으로 시작.

### 11.3 피드백

- 휴식 종료 시 비프. 안드로이드는 진동도 낸다(`햅틱` 설정을 따름).
- 눌렀을 때의 햅틱은 §11.3.1.
- **급감 경고**: 같은 운동에서 직전 본세트보다 무게가 같거나 내려갔는데(허용 오차 0.1kg) 횟수가 40% 이상 줄면 "여기서 마무리해도 좋아요"(휴식 화면의 `다음` 안내 아래에 작게 보인다). 무게를 내렸는데도 크게 줄었다면 더 지친 것이다. 직전 세트가 웜업이거나 이번 세트가 직전보다 무거우면 비교하지 않는다. 보조 무게 운동은 숫자가 작을수록 무거운 것으로 본다.
- **추천·경고 표시**: 규칙 엔진의 `reason`은 계획 화면(줄에는 결론, 줄 시트에는 전문)에만, `warnings`는 세션 시작 화면 배너에(2차, 미구현). 배너는 닫으면 같은 근거로는 다시 띄우지 않는다.
- 삭제·초기화·덮어쓰기·세션 종료 전에는 확인.

### 11.3.1 햅틱

**방식.** iOS Safari에는 `navigator.vibrate`가 없다. 눌리는 컨트롤 위에 투명한 `<input type="checkbox" switch>`(덮개)를 덮고, 손가락이 덮개에 직접 닿을 때 나는 시스템 틱을 쓴다. 덮개의 `change`가 아래 버튼의 `data-act` 처리(`dispatch`)로 이어지며 한 번 누름에 동작도 한 번이다. 덮개는 보조 기술에서 숨기고(`aria-hidden`, `tabindex=-1`) 버튼 라벨이 그대로 읽힌다. 안드로이드(`navigator.vibrate`가 있는 기기)는 덮개 없이 버튼 `click`에서 15ms 진동을 낸다.

**실기기 시험 결과(iPhone, iOS 27.2, Safari·Chrome).** 손가락이 스위치에 직접 닿으면 틱이 나고, 코드가 거는 `label.click()`·`input.click()`은 제스처 안(`pointerdown`·`click`·`pointerup`)에서도 틱이 나지 않았다. 지연 호출(`setTimeout`)과 연속 2연타도 같다.

**넣는 곳.** `N회 했어요`와 횟수 −/+, 체감 선택, 계획의 운동 시간 −/+, 시간 운동의 시간 −/+·`N분 했어요`, 휴식 타이머 버튼, `다음 세트 시작`, `한 세트 더`, `다음 운동으로`, `세션 종료`(주 버튼일 때), `시작`, `지금 운동으로`. 한 번 누르면 틱 한 번이며 종류는 구분하지 않는다. 비활성 버튼에는 덮개를 그리지 않는다.

**넣지 않는 곳.** 머리·시트 머리의 글자 버튼, 순서 손잡이(끌기와 충돌할 수 있음), 입력 칸, 시트 안의 버튼(무게 −/+, `kg ⇄ lbs` 포함), 글자만 있는 조용한 버튼(`운동 추가`, `순서 바꾸기`, `기록 버리고 처음으로`, 목록 화면의 `세션 종료`).

**아이폰에서 불가능한 것.** 타이머 종료처럼 사용자가 누르지 않은 순간의 햅틱, 도달·초과 여부에 따라 패턴을 바꾸는 것, 2연타 같은 코드로 만드는 패턴. 휴식 종료는 소리 알림을 쓴다.

**설정.** 설정 시트의 `햅틱`(기본 켜짐). 끄면 덮개를 그리지 않고 진동도 내지 않는다.

**남은 실기기 확인.** 홈 화면 웹앱, 빠른 연타 때 빠지는 틱, 덮개 때문에 눌림이 어색한 곳.

### 11.4 애니메이션

- 반복·세트 기록에 즉시 반응하고, 휴식에 들어가면 상태가 눈에 띄게 바뀐다.
- 운동별 동작은 데이터로 정의해서 운동 추가가 쉽게.
- `prefers-reduced-motion`이면 움직임을 줄인다.
- 스타일은 미정 (§13).

### 11.5 데이터 저장

- 로컬 저장 + JSON 기록 복사(클립보드).
- 저장 대상: 운동 카탈로그(§3)와 세션 템플릿(§7)은 코드에 두고, 확정된 세션 기록, 진행 중 세션 `draft`, 운동별 증량 폭 `increments`, 앱 설정(체중·표시 단위 포함)을 localStorage에 둔다 (§14.4). 앞으로 `coach_notes`(§10.1)를 더한다.
- Google Sheets 연동은 선택. 실패해도 로컬 기록은 유지.

### 11.6 구현 시 주의할 점

- **iOS 오디오**: 사용자 제스처 안에서 만든 `AudioContext`만 소리가 난다 → 첫 탭에서 만들어 두고 재사용.
- **`[hidden]` 무력화**: 자체 `display`가 있는 요소는 브라우저 기본 `[hidden]`이 안 먹힌다 → `[hidden]{display:none}` 규칙을 따로 둘 것.
- **헤드리스 Chrome 캡처**: 창 폭이 최소 500px라 375px 확인은 iframe(`width:375px`)으로. `requestAnimationFrame` 애니메이션은 중간 프레임으로 찍힐 수 있음.
- **외부 폰트**: Pretendard(jsDelivr)와 Oswald(Google Fonts) 두 곳에서 불러온다. 연결이 없거나 막혀도 모든 화면이 기기 기본 글꼴로 동작해야 한다. 숫자 폰트의 대체 순서는 Pretendard → 기기 기본 글꼴이다.
- **Apps Script 재배포**: `새 배포`는 URL이 바뀐다 → 배포 관리 → 편집 → `새 버전`으로.

### 11.8 시트

- **운동 시트**: 운동 이름을 누르면 열린다. 위에서부터 무게(`−` 값 `+`, `kg ⇄ lbs`, `증량 폭 · 직접 입력` 줄), `오늘`(세트 줄, 눌러서 고치기, `메모` 줄), 지난 메모, 직전 기록(읽기 전용). 시간 운동은 무게 칸이 없다.
- **운동 설정 시트**: 칸은 `시작 무게`(기록이 있으면 `지금 무게`)와 `증량 폭` 둘이다. 지금 하는 운동에 이미 세트가 있어도 `지금 무게`를 바꾸면 다음 세트부터 그 무게가 쓰이고, 이미 기록한 세트의 무게는 바뀌지 않는다. 칸 아래에, 아래에 `kg ⇄ lbs` 버튼이 있다. 표시 단위(kg / lbs)에 맞춰 보이고 받는다. `단위` 입력 칸은 없다. 운동 시트의 무게 값이나 `증량 폭` 줄을 누르면 열린다.
  - 미측정 운동이 지금 할 운동이 되었는데 무게가 없으면 시트가 저절로 뜨고(버튼은 `이 무게로 시작`), 무게를 넣기 전에는 세트를 기록할 수 없다. 닫아도 세트 화면의 주 버튼이 `시작 무게 정하기`로 바뀌어 시트를 다시 연다.
- **줄 시트·뺀 운동 시트**: §11.1 세션 시작.
- **같은 운동은 한 번만**: 한 세션에 같은 운동이 두 번 들어가지 않는다. `운동 추가` 목록에는 이미 세션에 있는 운동이 나오지 않고, 생략하거나 시간에 맞춰 뺀 운동만 `생략함 · 복원`으로 나와 누르면 추가 대신 복원된다. `다른 운동으로 대체` 목록에는 세션에 이미 있는 운동(생략한 것 포함)이 나오지 않는다.
- **시트 입력 유지**: 시트가 열려 있는 동안 화면이 다시 그려져도(휴식 종료 등) 입력 중인 칸의 값·포커스·커서 위치를 유지한다.
- **세트 고치기 시트**: `무게`·`횟수` 숫자 칸, `체감` 3택, `웜업 세트` 스위치, `kg ⇄ lbs`, `메모`, `저장`, `세트 삭제`(확인).
- **메모 시트**: 운동 메모와 세션 메모 각각 한 칸과 `저장`.
- **설정 시트**: `체중`, `휴식 끝 소리`·`햅틱` 스위치, `설정 저장`, 저장된 세션 수, `기록 복사`·`전체 기록 복사`(§14.11), `기록 서버` 구역(서버 주소가 있을 때만, §14.11), `모든 데이터 지우기`(확인 두 번).
- **운동 추가·대체의 고르기 시트**: 카탈로그 전체를 부위(패턴)별로 묶어 보여 준다. 미측정 운동은 이름 옆에 `미측정` 태그. 대체 시트는 같은 패턴·템플릿 후보(`대체 후보`)를 위에, 나머지를 아래에 둔다. `unsupported` 운동은 넣지 않는다.

### 11.9 홈 화면 웹앱

이 앱은 휴대폰 홈 화면에 추가해 전체 화면으로 쓰는 것을 기본으로 한다. 브라우저 탭에서도 같은 화면이 동작해야 한다.

- **설치 (아이폰)**: 사파리에서 앱 주소를 열고 `공유` → `홈 화면에 추가`. 사파리 설치를 권한다. 크롬(iOS)에서도 `공유` → `홈 화면에 추가`가 있지만, 크롬이 만드는 바로가기는 크롬 안에서 열려 전체 화면이 아닐 수 있다(실기기에서 확인할 것).
- **선언**: `manifest.webmanifest`(이름 `운동`, `display: standalone`, 바탕·테마 색은 바탕 토큰 값, 아이콘 192·512·maskable)와 `index.html`의 `apple-mobile-web-app-*` 메타, `apple-touch-icon`(180). 상태 표시줄 스타일은 `default`(바탕이 밝아서 검은 글자). `black-translucent`는 글자가 흰색이라 밝은 바탕에서 읽히지 않는다.
- **서비스 워커는 없다.** `main` 푸시가 곧 배포라서 오래된 캐시를 남기지 않는다. 오프라인에서는 열 수 없고, 폰트는 연결이 없으면 기기 기본 글꼴로 보인다.
- **저장소가 분리된다.** 홈 화면 웹앱과 사파리·크롬 탭의 `localStorage`는 서로 다르다. 탭에서 쓰던 기록 중 `records/`에 없는 것은 웹앱에서 보이지 않는다. 서버에 연결하면(§14.11) 두 쪽 모두 같은 서버를 거쳐 맞춰진다. 연결 전에는 쓰던 쪽 설정의 `기록 복사`로 복사해 레포 `records/`에 파일로 올린다.
- **알림(토스트)**: 위쪽 내용을 가리지 않게 가장 아래 층 바로 위에 띄운다. 시트가 열려 있으면 시트 윗단 위, 아니면 하단 주 버튼 발판 윗단 위다. 저장하면서 시트가 닫혀도 떠 있는 알림은 그 자리에서 발판 위로 다시 자리를 잡는다.
- **안전 영역과 높이**: 위·아래 안전 영역(`env(safe-area-inset-*)`)을 머리 줄·토스트·시트·하단 주 버튼에 적용하고, 시트 높이는 지금 보이는 영역(`visualViewport`)에서 위쪽 안전 영역을 뺀 값으로 제한한다. 규칙은 `STYLE-GUIDE.md`.
- **웹앱에서 달라질 수 있는 동작(실기기 확인)**: 진행 중 세션 복구(앱이 백그라운드에서 종료되면 휴식 타이머는 정지 상태로 복구된다), 30분 방치 자동 저장(`visibilitychange`), 화면 켜짐 유지(`wakeLock`은 지원하지 않는 버전에서 조용히 실패), 햅틱 덮개, 기록 복사(클립보드 실패 시 읽기 전용 텍스트 시트), `prompt`·`confirm` 대화상자, `records/` 자동 합치기(연결이 있을 때만).

## 14. 데이터 모델

앱이 저장하거나 주고받는 모든 데이터의 정식 모양이다. 코드는 이 모양만 읽고 쓴다.

### 14.1 원칙

- 무게 단위는 kg 하나다. 저장 데이터와 로직은 kg 숫자만 다룬다. 파운드는 입력 보조 칸과 보조 표기(§3.1.1)에만 쓰이고 저장되지 않는다.
- 운동(카탈로그)에는 무게도 단위도 없다. 무게는 기록에서만 나온다.
- 기구 식별·기구 등록이 없다. 부분 반복을 기록하지 않는다. 세트에는 횟수 하나가 있다.
- 같은 사실은 한 곳에만 저장한다. 카탈로그에서 알 수 있는 값은 기록에 복사하지 않는다.
- 배열 순서가 곧 순서다. 운동 순서와 세트 번호를 따로 저장하지 않는다.
- 계산으로 얻는 값(추천, 예상 시간, 볼륨, 세트 번호)은 저장하지 않는다.
- 아는 필드만 검사하고 모르는 필드는 지우지 않는다. 변환·불러오기·기록 복사가 새 필드를 그대로 통과시킨다.

### 14.2 값 형식

| 종류 | 형식 | 예 |
|---|---|---|
| 날짜 | 로컬 `YYYY-MM-DD` 문자열 | `2026-11-14` |
| 시각 | ISO-8601 UTC(`Z`) | `2026-11-14T00:53:16.206Z` |
| 시간 길이 | 초 정수, 필드 이름 `*_sec` | `rest_sec: 90`, `duration_sec: 900` |
| 무게 | kg 숫자, 소수 둘째 자리 | `22.68` |
| 횟수·세트 수 | 정수 | `10` |
| 메모 | 문자열. 비면 필드를 두지 않는다 | |

시간 운동의 화면 입력은 분 단위로 하고 저장은 초로 한다.

### 14.3 열거 값

| 필드 | 값 |
|---|---|
| `pattern` | `vertical_pull`, `horizontal_pull`, `horizontal_push`, `vertical_push`, `rear_delt`, `lateral_delt`, `elbow_extension`, `elbow_flexion`, `squat`, `hinge`, `lunge`, `knee_extension`, `knee_flexion`, `calf`, `core`, `cardio` |
| `load` | `weight`, `assist`, `none` |
| `measure` | `reps`, `seconds` |
| `weight_basis` | `total`, `per_side` |
| `progression` | `double`, `linear`, `none` |
| 슬롯 `priority` | `core`, `main`, `optional` (시간이 부족하면 optional → main 순으로 뺀다) |
| `session_type` | 템플릿 id (`upper`, `lower`, `free`). 모르는 값은 문자열 그대로 보인다 |
| `feel` | `light`, `ok`, `heavy` (없을 수 있음) |
| 항목 `status` | `pending`, `done`, `skipped` |
| draft `phase` | `plan`, `active` |
| 추천 `kind` | `up`, `down`, `hold`, `wait`, `fail`, `reps` (없을 수 있음) |

### 14.4 저장소와 엔터티

**저장소** localStorage 두 키.

- `workout_v1`: `{version: 3, sessions[], settings, increments}`. 세션과 설정이 바뀔 때만 쓴다.
- `workout_v1_draft`: 진행 중 세션. 세트를 기록할 때마다 이 키만 다시 쓴다. 불러올 때 `draft.id`가 이미 `sessions`에 있으면 버린다.
- `workout_v1_pre3`: v3 이전 저장소의 원본 사본. 한 번만 만들고 덮어쓰지 않는다.
- `workout_v1_bad`: 불러올 때 형식이 맞지 않아 빼 둔 세션의 보관소.

**settings**: `bodyweight_kg`(number\|null), `sound`(bool), `haptic`(bool, 기본 true), `target_sec`(마지막으로 쓴 운동 시간, 새 세션의 기본값), `weight_unit`(`kg`\|`lbs`, 표시용).

**increments**: `{운동 id: kg}`. 카탈로그 기본값과 다른 운동만, 값은 양수.

**SessionRecord** (끝난 세션)

| 필드 | 타입 | 필수 | 뜻 |
|---|---|---|---|
| `id` | string | ● | 세션 식별·중복 판정 키 |
| `date` | 날짜 | ● | 시작한 날 |
| `session_type` | string | ● | 템플릿 id |
| `started_at` | 시각 | | 시작 시각 |
| `duration_sec` | int | | 시작~마지막 기록 길이. `세션 종료`를 누른 시각은 쓰지 않는다. 생략한 운동의 세트는 마지막 기록에 넣지 않는다. 마지막 기록은 세트 `at` 중 가장 늦은 것이고, 시간 운동(유산소)은 기록한 시각 `at`을 쓴다. 시간 운동에 `at`이 없으면 마지막 세트 시각 + 그 운동의 `duration_sec`. 기록이 없거나 시작 시각이 없으면 60. 계산값이 60보다 작으면 60으로 올린다(최소 1분) |
| `bodyweight_kg` | number | | 그날 체중 |
| `notes` | string | | 세션 메모 |
| `watch_note` | string | | 다음에 지켜볼 것 |
| `exercises` | ExerciseLog[] | ● | 수행 순서. 1개 이상 |

**ExerciseLog**: `exercise_id`(●, 카탈로그 id), `sets`(●, SetLog[], 웜업 포함 수행 순서, 1개 이상), `note`(오늘 메모), `next_note`(다음 목표 메모, 자유 문장).

**SetLog**: `weight_kg`(`load`가 `none`이 아니면 필수. `per_side`면 한 쪽 무게. `assist`면 보조 무게로 0이면 보조 없음), `reps`(`measure`가 `reps`면 필수), `duration_sec`(`measure`가 `seconds`면 필수), `is_warmup`(bool), `feel`, `note`, `at`(기록 시각). 해당 없는 필드는 두지 않는다.

**Draft** (진행 중 세션): `id`(저장하면 세션 `id`가 된다), `date`, `session_type`, `phase`, `current`(지금 항목의 `uid`, plan이면 null), `started_at`(active에서), `target_sec`(이 세션 운동 시간), `bodyweight_kg`, `notes`, `items[]`.

**DraftItem**: `uid`, `exercise_id`, `slot`(템플릿 슬롯 번호, 추가한 운동은 null), `priority`, `status`, `target`, `base_sets`(시간 맞추기 전 세트 수), `pre`(균형 슬롯 설명 머리말), `sets`(SetLog[]), `note`, `auto`(시간 맞추기가 자동으로 뺀 운동), `keep`(직접 복원해서 자동으로 빼지 않는 운동), `goal_kg`(웜업 판정에 쓰는 목표 무게. 계획 때의 무게이고 `운동 설정`에서 무게 칸을 직접 고칠 때만 바뀐다. 시간 운동에는 없다). 진행 중 세트에는 `wu_manual`(세트 고치기 스위치로 웜업 여부를 직접 바꾼 세트)이 붙을 수 있고, 저장할 때 지운다.

- `target`: `{weight_kg, reps, sets}` 또는 시간 운동이면 `{duration_sec, sets}`. `weight_kg`는 지금 무게이고 미측정이면 `null`. 휴식 시간은 카탈로그에서 읽는다.

**ExportFile**: `{version: 3, exported_at, settings, increments, sessions}`. 진행 중 세션은 내보내지 않는다.

**내보내기 방식**: 설정의 `기록 복사` 버튼(기본은 서버나 `records/`에 없는 세션만, `전체 기록 복사`는 전부. §14.11)이 ExportFile JSON을 클립보드에 복사하고 `기록을 클립보드에 복사했어요` 토스트를 띄운다. 파일은 내려받지 않는다. `navigator.clipboard.writeText`는 탭 핸들러 안에서 바로 호출한다(iOS 사파리). 복사에 실패하면 JSON이 전체 선택된 읽기 전용 텍스트 영역을 시트(`기록 복사`)로 띄워 직접 복사하게 한다. 가져오기 기능은 없다.

### 14.5 저장과 계산

저장하는 것: 세트의 무게·횟수·시간·웜업·체감·메모·시각, 세션 날짜·종류·시작 시각·길이·체중·메모, 증량 폭 덮어쓰기, 설정.

계산하는 것: 추천 무게·횟수·세트·이유, 예상 시간과 세트 시간, 경과·남은 시간, 시간 띠(세션 막대), 볼륨, 본세트 수, 오늘 정리, 세트 번호, 휴식 시간, 목표 대비 단계, lbs 표기. 화면 상태(카운터, 휴식 타이머, 화면 종류)는 저장하지 않는다.

### 14.6 무게 없는 운동

운동의 `load`와 `measure`가 세트에 어떤 필드가 있는지 정한다.

| 종류 | 예 | `load` | `measure` | 세트 | `progression` |
|---|---|---|---|---|---|
| 무게 | 랫풀다운, 덤벨 프레스 | `weight` | `reps` | `{weight_kg, reps}` | `double`, `linear` |
| 보조 | 어시스트 풀업·딥 | `assist` | `reps` | `{weight_kg(보조), reps}` | `double` (보조를 줄이는 쪽이 증량) |
| 맨몸 횟수 | 푸시업 | `none` | `reps` | `{reps}` | `none` |
| 시간 | 플랭크 | `none` | `seconds` | `{duration_sec}` | `none` |
| 유산소 | 실내 사이클 | `none` | `seconds` | `{duration_sec}` 1개 | `none` |

`load`·`measure`·`weight_basis`는 운동을 만든 뒤 바꾸지 않는다(옛 기록의 뜻이 변하므로). 바꿔야 하면 새 운동으로 만든다.

### 14.7 데이터 버전

| 버전 | 모양 |
|---|---|
| 1 (버전 없음, `version: 1`) | 운동별 `unit`, lb 무게가 섞여 있음, `exercise_type`, `weight`, 분 단위 |
| 2 (`kg_v: 2` 저장소, `version: 2` 내보내기) | 무게는 kg, 필드 이름은 v1과 같음 |
| 3 | 이 문서의 모양 |

- 선택 필드를 더하는 것은 버전을 올리지 않는다. 이름·의미·삭제·필수화가 바뀌면 올린다.
- 파일의 `version`이 앱보다 크면 불러오기를 거부한다. 버전이 없는 세션 배열·단일 세션 파일은 v1로 보되, 필드가 이미 v3 모양이면 그대로 읽는다.

### 14.8 변환 (v1·v2 → v3)

읽을 때 한 번 변환하고, 이미 v3인 데이터에 다시 적용해도 바뀌지 않는다. 변환 전 저장소 원본은 `workout_v1_pre3`에 둔다.

| 이전 | v3 |
|---|---|
| 세션 `id` 없음 | `legacy:<date>:<session_type>` (같은 날 같은 종류가 더 있으면 `:2`, `:3`) |
| 세션 `duration_min` | `duration_sec` = × 60 |
| 세션 `next_targets.watch`, `add_next_time` | `watch_note` (`add_next_time`은 `다음에 추가: …`로 이어 붙임) |
| 세션 `next_targets[운동 id]` | 그 ExerciseLog의 `next_note` |
| 빈 `notes`, `null` 체중 | 필드 삭제 |
| 운동 `exercise_type` | `exercise_id` |
| 운동 `order`, `equipment`, `equipment_id`, `unit`, `weight_basis`, `weight_kg_approx` | 삭제 |
| 유산소 운동 `duration_min` (세트 없음) | `sets: [{duration_sec: 분 × 60}]` |
| 세트 `weight` | `weight_kg`. 운동 `unit`이 `lb`면 `× 0.45359237`을 소수 둘째 자리로(50lb → 22.68). `unit`이 없는 리버스 펙덱·레그 컬·레그 익스텐션의 숫자 무게도 lb로 본다 |
| 세트 `set_number`, `input_mode` | 삭제 |
| 세트 `feel: null`, 빈 `note` | 필드 삭제 |
| `settings.target_min` | `settings.target_sec` = × 60 |
| `prefs[id].increment` | `increments[id]` = 절댓값(lb 기구는 lb 값을 kg으로 환산). 카탈로그 기본값과 같으면 두지 않는다 |
| `prefs[id].unit`, `prefs[id].start` | 삭제 |
| draft `target_min` | `target_sec` = × 60 |
| draft 항목 `exercise_type`, `cur_weight`, `target.weight` | `exercise_id`, `target.weight_kg` (lb 기구는 환산) |
| draft 항목 `duration_min`, `target.duration`, `target.rest_sec`, `reason` | `target.duration_sec`(× 60), 나머지 삭제 |
| draft 세트 | 세트 변환과 같음. 유산소 `{duration_min}` → `{duration_sec}` |

### 14.9 불러오기 검사

받는 모양: 내보내기 파일, 세션 배열, 단일 세션(`records/`의 파일은 세션 하나). 불러온 뒤 세션마다 검사한다.

- 필수: `date`가 실존하는 날짜, `session_type`, `id`(변환이 채운다), `exercises`가 배열.
- 운동은 `exercise_id`와 `sets` 배열이 있어야 한다. 유효한 세트가 하나도 없는 운동은 뺀다. 유효한 운동이 없는 세션은 건너뛴다.
- 세트: `weight_kg`는 0 이상 1000 이하, `reps`는 1~200 정수, `duration_sec`은 1~14400 정수. 숫자 문자열은 숫자로 바꾼다. 카탈로그의 `load`·`measure`가 요구하는 필드가 없으면 그 세트를 뺀다. `feel`이 열거값이 아니면, `at`이 읽을 수 없거나 하루 넘게 미래면 그 필드만 뺀다.
- 카탈로그에 없는 `exercise_id`는 기록을 보관하고 추천·균형 계산에서 쓰지 않는다.
- 체중은 20~300kg 밖이면 그 필드만 뺀다. 증량 폭은 카탈로그에 있고 `load`가 `none`이 아닌 운동의 양수(100 이하)만 받는다.
- 중복: 저장된 세션과 같은 세션이면 더하지 않는다(§14.10 판정). 같은 날 같은 종류라도 다른 세션이면 둘 다 둔다.
- 불러올 때(저장소)는 같은 검사를 하되 범위 밖 값은 지우지 않고, 형식이 맞지 않는 세션만 `workout_v1_bad`로 옮긴다.
- 세션은 `date`, `started_at`, `id` 순으로 정렬해 둔다. 마지막 원소가 가장 최근이다.

### 14.10 레포 기록

- 위치: `workout/records/`. 세션당 파일 하나, 내용은 version 3 세션 객체 하나. 파일 이름은 `날짜-종류.json`(같은 날 같은 종류면 `-2` 붙임, 자유 세션은 `날짜-free.json`).
- 목록: `records/index.json`은 파일 이름 문자열 배열이다. 정적 사이트라 폴더를 읽을 수 없어 목록이 있어야 불러온다. 새 기록은 파일을 넣고 이 배열에 이름을 한 줄 더한다.
- 불러오기: 앱이 뜬 뒤 목록과 파일을 `fetch`로 읽고, 불러오기 검사(14.9)를 거쳐 저장된 세션과 합친다. 화면은 먼저 그리고, 새로 들어온 세션이 있을 때만 진행 중 세션이 없고 시트가 닫혀 있으면 다시 그린다. 요청 실패·깨진 파일·검사 탈락은 조용히 건너뛴다.
- 합치기: 저장된 쪽을 우선하고 레포 기록은 없는 것만 더한다. 파일의 설정·증량 폭은 쓰지 않는다. 모든 데이터 지우기 뒤에는 다음 실행에서 다시 들어온다.
- 같은 세션 판정(`id`가 다를 때): `date`와 `session_type`이 같고, 양쪽에 세트 `at`이 있으면 가장 이른 `at`이 같을 때, 없으면 `started_at`이 같을 때, 그것도 없으면 운동 순서와 운동별 세트 수가 같을 때.

### 14.11 서버 동기화 (구글 시트)

기록을 기기 밖에도 두는 덧붙임 기능이다. 네트워크가 없어도 앱은 지금처럼 완전히 동작하고, 서버는 보내고 받는 것만 맡는다.

**구성**
- `sync.js`(`window.Sync`)가 서버 호출을 맡는다. 서버 주소는 `sync.js` 맨 위 상수 `URL`이고 비어 있으면 아무것도 하지 않는다(설정 화면에 서버 구역도 나오지 않는다). 비밀번호는 저장소에 없고, 로그인해서 받은 토큰만 기기 `localStorage`의 `workout_v1_sync`에 둔다.
- 서버는 구글 시트에 붙인 Apps Script 웹앱(`apps-script.gs`)이다. 시트 탭 `세션`의 한 행이 세션 하나다: `id`, `날짜`, `종류`, `시작`, `시간(초)`, `운동`(운동 id), `갱신`(서버가 쓴 시각), `세션 JSON`(세션 객체 전체). 읽기·쓰기는 모두 인증이 필요하고 모든 호출은 POST다.
- 호출 방식은 civic과 같다: `fetch(주소, { method: 'POST', body: JSON })`에 `Content-Type`을 주지 않아(text/plain) CORS 사전 요청이 없다. Apps Script는 `/exec`를 `script.googleusercontent.com`으로 302 리다이렉트하고 응답에 `Access-Control-Allow-Origin: *`를 붙이며, `fetch`가 리다이렉트를 따라간다. 응답은 글자로 받아 직접 JSON으로 읽는다(JSON이 아니면 `서버 응답을 읽지 못했어요`, 예: 액세스가 "모든 사용자"가 아니라서 로그인 HTML이 올 때). 25초 안에 응답이 없으면 네트워크 실패로 본다.
- 동작(`action`): `login`(비밀번호 → 토큰), `check`, `logout`, `list`(세션 목록), `upsert`(`sessions` 최대 50개), `data_list`·`data_put`(데이터 탭, 아래). 삭제 동작은 없다. 시트에서 행을 지워도 기기에 세션이 남아 있으면 다음 연결 때 다시 올라간다.
- 잠금: `login`·`logout`·`upsert`는 모두 스크립트 잠금 안에서 처리한다. 로그인 실패 횟수(10분에 8번이면 잠금)와 토큰 목록(최대 5개)을 읽고 쓰는 일이 원자적이라 병렬 요청으로 실패 제한을 피할 수 없고, 두 기기가 동시에 연결해도 토큰이 사라지지 않는다. 틀린 로그인은 잠금 안에서 1초 쉰다. 잠금을 20초 안에 못 잡으면 `busy`로 응답한다.
- `upsert` 검사는 항목별이다. 요청 모양(`sessions`가 배열이 아니거나 비었거나 50개 초과)이 틀리면 `shape`로 요청 전체를 거절하고, 그 밖에는 항목마다 `id`(문자열, 100자 이하), `date`(실존하는 `YYYY-MM-DD`), `session_type`(40자 이하), `exercises` 배열, 세션 JSON 4만 5천 자 이하를 확인해 통과한 것만 저장한다. 응답은 `{ ok, saved: [id], rejected: [{ id, index, error }] }`다. 같은 요청 안에 같은 `id`가 여러 번 있으면 마지막 것만 쓴다. 시트가 5천 행이면 새 행은 `full`로 거절한다. 시트의 날짜 칸은 텍스트 서식이라 날짜로 바뀌지 않고, 읽을 때는 `세션 JSON` 칸만 쓴다. 깨진 JSON 행은 건너뛰고 `bad`로 센다. 예외 응답은 `{ ok: false, error: 'server' }`뿐이고 내부 문구는 내려가지 않는다.
- **같은 `id`에 내용이 다를 때**: `id`는 같은 세션이다. 서버는 마지막으로 올라온 내용(갱신 시각이 최신)을 갖는다. 기기는 서버 목록을 받을 때 같은 `id`인데 내용이 다르면 서버 내용으로 맞추고, 교체되는 기기 쪽 내용은 `workout_v1_replaced`에 보관한다. 서버를 기준으로 삼아 두 기기가 서로 덮어쓰며 되풀이하지 않는다. 새 세션의 `id`는 무작위라 이 경우는 `id`가 없던 시절의 `legacy:날짜:종류` 세션에서만 생긴다.

**데이터 탭 (세션 밖 데이터의 범용 저장소)**
- 세션은 쌓이는 기록(`id`로 추가·갱신)이고 세션 밖 데이터(설정, 증량 폭, 앞으로 생길 것)는 덮어쓰는 문서라서, 시트 탭을 `세션`과 `데이터`로 나눴다. 데이터가 늘어도 서버(Apps Script)는 다시 배포하지 않고 앱 코드만 바꾼다.
- 시트 탭 `데이터`: 열은 `키`, `갱신 시각`, `JSON`이고 키 하나가 한 행이다. `setup`이 `세션`과 `데이터` 두 탭을 모두 만든다. 이미 `setup`을 해 둔 사용자가 새 코드를 올릴 때는 `setup`을 다시 실행하지 않아도 된다(서버가 `데이터` 탭을 처음 쓸 때 만든다).
- 서버는 키 이름의 뜻을 모른다. 검사는 키 형식(`A-Z a-z 0-9 _ . : -`, 1~64자), 값 크기(JSON 4만 5천 자 이하), 키 개수(200개), 갱신 시각 형식(ISO 8601 UTC)뿐이다. 갱신 시각이 서버 시계보다 하루 넘게 미래면 `time`으로 거절한다.
- `data_list`는 전체 키를 `{ key, updated_at, value }`로 돌려준다(깨진 행은 건너뛰고 `bad`로 센다). `data_put`은 `items`(최대 20개, `{ key, updated_at, value }`)를 받아 `{ saved, stale, rejected }`를 돌려준다. 두 응답에는 서버 시각 `now`가 들어 있다. 인증·잠금·항목별 검사·같은 요청 안 같은 키 처리(가장 최신 시각)는 세션과 같다.
- **키는 필드 하나가 하나다.** 값 하나가 키 하나이고 갱신 시각도 키마다 따로다. 그래서 한 필드를 바꿔도 다른 필드의 더 최신 값이 되돌아가지 않는다. 지금 쓰는 키는 `settings.bodyweight_kg`(체중), `settings.target_sec`(운동 시간), `settings.weight_unit`(무게 단위)와 운동마다 `increments.<운동 id>`(증량 폭, 카탈로그 기본값이면 `null`)다. 키는 약 30개이고 상한(200개)을 넘기지 않아야 한다(카탈로그가 크게 늘면 그때 나눈다).
- **충돌 규칙: 키마다 갱신 시각이 나중인 쪽이 이긴다.** 서버에 있는 시각이 보낸 시각보다 나중이면 덮어쓰지 않고 서버 값을 `stale`로 돌려주며, 기기는 그 값을 받아들인다. 같은 시각이면 덮어쓴다(재전송이 안전하다).
- **기기 시계 보정.** `갱신 시각`은 서버 시계 기준이다. 기기는 서버 응답의 `now`와 자기 시계의 차이(`skew`)를 기억해 두고, 값을 바꾼 시각은 기기 시계로 적어 둔 뒤 보낼 때만 `skew`를 더한다. 받은 서버 시각은 `skew`를 빼서 기기 시계로 바꿔 비교한다. 기기 시계가 몇 시간·하루 넘게 틀려도 변경이 되돌려지거나 영구히 갈라지지 않는다. 오차는 응답이 오가는 시간(수 초) 정도다. 연결할 때 서버 키를 먼저 받으므로 보내기 전에 `skew`가 정해진다.
- **기본값은 올리지 않는다.** 사용자가 한 번도 바꾸지 않은(`at`이 없고 값이 기본값인) 키는 서버에 올리지 않는다. 새 기기의 기본값이 정당한 값처럼 서버를 덮는 일을 막는다. 사용자가 바꾼 값은 기본값으로 되돌려도 올린다.
- 기기에서 쓸 키는 `app.js`의 `syncKeys()` 한 곳에 `{ def, get, parse, set }`로 적는다. `def`는 기본값, `get`은 지금 값, `parse`는 서버 값을 `{ ok, value }`로 정리(무효면 `ok: false`), `set`은 값을 반영한다. 키를 늘리는 일은 이 목록에 항목을 더하는 것(필드 목록 `SYNC_SETTINGS`에 이름을 더하거나 운동을 카탈로그에 더하는 것)뿐이다. 값이 바뀌었는지는 저장할 때마다 값의 정규화한 문자열(`sig`)을 비교해 알아내므로, 값을 바꾸는 곳마다 따로 알릴 필요가 없다. 서버에 있어도 이 앱이 모르는 키는 무시한다.
- `settings` 중 `sound`(휴식 끝 소리)와 `haptic`(햅틱)은 키가 없다. 기기마다 달라도 되는 값이라서다(헬스장에서 쓰는 폰은 소리를 켜고 집의 태블릿은 끄는 식).
- 기기 상태(`workout_v1_sync`): `at[키]`(마지막으로 바꾼 시각, 기기 시계), `sig[키]`(그때 값의 문자열), `dq`(보낼 키 대기열), `dr`(서버가 거절해 더 안 보내는 키), `ov`(다른 기기의 값으로 바뀐 키), `skew`. 대기열·재시도는 세션과 같다(저장하면 바로 올리고, 실패하면 남겨 두었다가 앱을 열 때·`online`·`지금 동기화`에서 다시 보낸다). 전송하는 사이에 값이 바뀌면(보낸 `at`과 지금 `at`이 다르면) 그 키는 대기열에 남아 끝난 뒤 한 번 더 보낸다.
- **동기화할 때 키마다 하는 일** (서버에 키가 없을 때와 있을 때):
  - 서버에 키가 없다: 기기에 `at`이 있으면 올린다. `at`이 없고 값이 기본값이 아니면(이 기능 이전부터 쓰던 값) 지금 시각으로 올린다. 기본값이면 아무것도 하지 않는다.
  - 서버에 키가 있고 기기에 `at`이 없다:
    - 기기 값이 기본값이면 서버 값을 받는다(두 번째 기기가 처음 연결하는 경우).
    - 값이 같으면 서버 시각을 받아 적는다.
    - 기기 값이 기본값이 아니고 서버 값이 기본값이거나 무효면 기기 값을 올린다.
    - 둘 다 기본값이 아니고 값이 다르면 서버 값을 유지한다. 덮인 기기 값은 `workout_v1_replaced_data`에 보관하고 설정에 `다른 기기의 값으로 바뀐 설정 N개 (이전 값은 기기에 보관)`를 한 줄 덧붙인다(`지금 동기화`를 누르면 이 줄은 사라진다).
  - 둘 다 시각이 있다: 서버가 더 나중이면 서버 값을 받고, 기기가 더 나중이면 올리고, 같으면 아무것도 하지 않는다.
- **서버 값이 무효하면** `parse`가 `ok: false`를 돌려주고, 기기는 서버 시각을 받아들이지 않고 자기 값을 지금 시각으로 올려 서버의 값을 고친다. 증량 폭은 운동별 키라서 한 운동의 무효한 값이 다른 운동의 값을 건드리지 않는다.
- 서버 값을 받아 적용한 뒤에는 저장하고 화면을 다시 그린다. 무게 단위가 바뀌었을 때는(진행 중 세션 중이어도) 열려 있던 시트를 닫고 곧바로 다시 그린다. 안 그러면 무게 −/+가 새 단위로 움직이는데 화면은 옛 단위로 남는다.
- `모든 데이터 지우기` 뒤에는 `at`·`sig`·대기열이 비므로 다음 동기화에서 서버 값이 돌아온다.
- 표시: 보낼 키가 남았으면 `보내지 못한 설정 N개`, 서버가 거절한 키가 있으면 `올리지 못한 설정 N개`, 다른 기기의 값으로 바뀐 키가 있으면 위의 한 줄을 설정의 `기록 서버` 구역에 조용히 덧붙인다.

**기기 쪽 동작**
- 연결: 설정의 `기록 서버` 구역에서 비밀번호를 넣고 `연결`(누르는 중 다시 눌러도 한 번만 처리한다). 끊기는 이 기기의 토큰만 지운다(서버 기록은 그대로).
- 저장: 세션을 저장하면(자동 저장 포함) 그 세션 `id`를 보낼 대기열에 넣고 바로 올린다. 실패하면 대기열에 남고, 앱을 열 때와 `online` 이벤트, `지금 동기화`에서 다시 보낸다. 한 번에 20개씩 보낸다. 동기화는 한 번에 하나만 돌고, 도중에 다른 요청이 오면 끝난 뒤 한 번 더 돈다. 응답에 `saved`도 `rejected`도 없으면(진행이 없으면) 멈추고 `서버 응답을 읽지 못했어요`로 표시해서 같은 요청을 되풀이하지 않는다.
- 거절된 세션: `rejected`로 돌아온 `id`는 대기열에서 빼고 `workout_v1_sync.rejected`에 둔다. 세션은 기기에 그대로 있다. 열 때·`online`에서는 다시 보내지 않고, `지금 동기화`를 누르면 한 번 다시 시도한다. 설정에는 `올리지 못한 세션 N개 (기기에는 그대로 있어요)`라고 조용히 알린다.
- 열 때: `records/` 합치기가 끝난 뒤 서버 목록을 받아 불러오기 검사(§14.9)를 거쳐 `addMissing`(§14.10 판정)으로 합친다. 검사에 걸려 합치지 못한 세션과 서버가 깨졌다고 센 행은 `읽지 못한 서버 세션 N개`로 보인다. 이어서 로컬 세션 중 서버 목록에 같은 세션(`sameSession`)이 없는 것을 모두 대기열에 넣는다. **처음 연결할 때의 이전도 같은 규칙이다**: 로컬과 `records/`에서 온 세션이 `id` 그대로(`legacy:날짜:종류` 포함) 올라가고, 이미 서버에 있는 세션은 다시 올라가지 않는다.
- 상태 문구: 연결 안 됨 / 연결됨(마지막 동기화 시각) / 동기화하는 중 / `서버에 닿지 않았어요`(네트워크 실패나 시간 초과) / `서버 응답을 읽지 못했어요`(JSON이 아닌 응답) / `서버가 요청을 받아들이지 않았어요 (코드)`(서버가 거절) / `서버가 바빠요` / `다시 연결해 주세요`(토큰이 무효). 보낼 것이 남았으면 `보내지 못한 세션 N개`를 덧붙인다. 새 색·크기 없이 `.sec`(700)·`.lbl`·`.btn`(600) 패턴만 쓴다.
- 서버에 있다고 아는 세션 `id`는 `workout_v1_sync.known`에 쌓는다(서버에서 받았거나 올린 것, `records/`와 같은 세션으로 판정된 것).
- 동기화하지 않는 것: 설정 중 소리·햅틱, 진행 중 세션(`draft`). (체중·운동 시간·무게 단위와 증량 폭은 데이터 탭으로 필드별로 동기화한다.)
- `모든 데이터 지우기`는 대기열과 `known`도 비운다. 서버에는 남아 있어 다음에 열 때 내려받는다. 서버 기록까지 지우려면 시트에서 행을 지운다.

**내보내기**
- `기록 복사`(기본)는 `known`에 없는 세션만 복사한다. 서버 주소가 있으면 버튼은 `기록 복사 (올라가지 않은 N개)`, 서버 주소가 비어 있으면 `기록 복사 (records/에 없는 N개)`다. 0개면 복사하지 않고 안내한다.
- `전체 기록 복사`는 저장된 세션 전부를 복사한다(비상용).
- `known`은 이 기기가 `records/`나 서버를 한 번도 못 읽었으면 비어 있고, 그때는 모든 세션이 "올라가지 않은 것"으로 센다.

**`records/` 자동 합치기를 없앨 것인가**: 남긴다. 서버 없이도 새 기기·새 설치에서 기록이 복원되는 읽기 전용 바탕이고, 서버 주소가 비어 있거나 서버가 막혀 있어도 추천이 이어진다. 비용은 열 때 요청 몇 개다. 서버를 쓰는 것이 몇 달 이어져 `records/`에 새 파일을 올릴 일이 없어지면 그때 새 기록 올리기만 멈추고 합치기는 그대로 둔다.

### 14.12 서버 설치 (사용자 절차)

`apps-script.gs`는 git으로 배포되지 않는다. 구글 시트에서 직접 붙여 넣는다. 레포에는 비밀번호나 시트 내용이 들어가지 않는다. 사용자는 코드 파일을 고치지 않는다: 7단계에서 주소만 Claude에게 주면 `sync.js`에 넣고 푸시한다.

1. 새 구글 시트를 만든다(이름은 자유, 예: `운동 기록`).
2. 메뉴 확장 프로그램 › Apps Script를 연다. 편집기에 이미 있는 `function myFunction() {}`를 모두 지우고 `workout/apps-script.gs` 내용을 통째로 붙여 넣은 뒤 저장(디스크 아이콘 또는 ⌘S)한다.
3. 왼쪽 톱니 아이콘(프로젝트 설정) › 맨 아래 스크립트 속성 › 속성 추가. 이름은 `PASSWORD`, 값은 비밀번호이고 저장한다. 웹앱 주소가 공개되어 있어 비밀번호 추측을 막는 것이 이 값뿐이므로 **12자 이상의 긴 문장**으로 정한다(사전에 나오는 단어·숫자만으로 하지 않는다). 앞뒤 공백·줄바꿈은 무시된다.
4. 왼쪽 `‹› 편집기`로 돌아와 위쪽 함수 선택 드롭다운에서 `setup`을 고르고 `▶ 실행`을 누른다. 처음에는 "승인 필요"가 뜬다.
   - `권한 검토` › 구글 계정 선택 › "Google에서 확인하지 않은 앱" 경고가 나오면 왼쪽 아래 `고급` › `(프로젝트 이름)(안전하지 않음)으로 이동` › `허용` 순서로 넘어간다(내가 만든 스크립트라 안전하다).
   - (새 버전으로 올리는 기존 사용자는 `setup`을 다시 실행하지 않아도 된다. `데이터` 탭은 서버가 처음 쓸 때 만든다.) 끝나면 시트에 `세션` 탭과 `데이터` 탭, 각 머리글이 생긴다(탭이 두 개다. `세션`은 쌓이는 기록, `데이터`는 설정 같은 덮어쓰는 값이다). 실행 로그에 `실행 완료`가 보이면 된다.
5. 오른쪽 위 `배포` › `새 배포`. 유형 선택의 톱니 아이콘을 눌러 `웹 앱`을 고른다.
   - 다음 사용자로 실행: `나`.
   - 액세스 권한이 있는 사용자: **`모든 사용자`**. `Google 계정이 있는 모든 사용자`를 고르면 앱이 로그인 화면(HTML)을 받아 모든 호출이 실패한다. 인증은 앱의 비밀번호·토큰이 한다.
   - `배포`를 누르고 나온 `웹 앱 URL`(`https://script.google.com/macros/s/…/exec`, 끝이 `/exec`)을 복사한다. `/dev`로 끝나는 테스트 주소가 아니다.
6. **확인**: 복사한 주소를 브라우저 주소창에 붙여 열었을 때 `{"ok":true}`가 보이면 배포가 된 것이다. 로그인 화면이나 오류 페이지가 보이면 5단계(액세스 권한)를 다시 본다.
7. 그 주소를 Claude에게 준다. Claude가 `workout/sync.js` 맨 위 `const URL = ''`에 넣고 푸시한다. 주소는 비밀이 아니고 비밀번호가 비밀이다. 푸시한 뒤 GitHub Pages에 반영되기까지 1~2분 걸리고, 그동안은 설정에 `기록 서버` 구역이 보이지 않는다(앱을 새로 고치거나 홈 화면 웹앱을 완전히 닫았다 다시 연다).
8. 앱 설정 › `기록 서버`에서 비밀번호를 넣고 `연결`한다. 처음 연결하면 이 기기의 세션과 `records/`의 세션이 모두 올라간다.
9. **기기마다 따로 연결한다.** 홈 화면 웹앱과 사파리(또는 크롬) 탭은 저장소가 서로 달라서 각각 한 번씩 연결해야 한다. 기기 토큰은 최대 5개만 유효하고, 6번째 연결은 가장 오래된 기기를 `다시 연결해 주세요` 상태로 바꾼다.

**운영 메모**
- 코드를 고친 뒤에는 배포 관리 › 편집(연필) › 버전 `새 버전`으로 올린다. `새 배포`는 주소가 바뀌어 `sync.js`가 깨진다.
- 모든 기기 연결 끊기: 비밀번호를 바꾸거나 편집기에서 `revokeAll`을 실행한다. 토큰에는 만료가 없으므로 기기를 잃어버렸을 때는 이 방법뿐이다.
- 웹앱은 콜드 스타트로 첫 응답이 1~3초 걸릴 수 있다.
- 시트에서 `세션 JSON`·`id` 칸과 `데이터` 탭은 고치지 않는다(`데이터` 탭을 손으로 고치면 갱신 시각 규칙 때문에 기기 값이 이길 수 있다). 날짜·종류·시간 칸은 읽기용이라 고쳐도 앱에 반영되지 않고 다음 업로드 때 덮어쓴다.

**오류 해석표** (설정 `기록 서버`의 문구 → 원인 → 할 일)

| 문구 | 원인 | 할 일 |
|---|---|---|
| 연결되지 않았어요 | 이 기기에 토큰이 없다 | 비밀번호를 넣고 `연결` |
| 토스트 `비밀번호가 맞지 않아요` | 3단계 값과 다르다 | 스크립트 속성 `PASSWORD`를 확인 |
| 토스트 `잠시 뒤에 다시 시도해 주세요` | 10분에 8번 틀려 잠겼다 | 10분 기다린다 |
| 토스트 `서버에 비밀번호가 정해져 있지 않아요` | `PASSWORD` 속성이 없다 | 3단계 |
| 서버에 닿지 않았어요 | 오프라인이거나 주소가 틀렸다 | 6단계의 `{"ok":true}` 확인, 인터넷 연결 확인 |
| 서버 응답을 읽지 못했어요 · 배포 설정을 확인해 주세요 | 응답이 JSON이 아니다(대개 액세스 권한이 `모든 사용자`가 아니거나 `/dev` 주소) | 5단계 |
| 서버가 요청을 받아들이지 않았어요 (코드) | 서버가 요청 전체를 거절(`shape`, `sheet`, `server` 등) | 스크립트를 최신 코드로 새 버전 배포, 시트의 `세션`·`데이터` 탭 확인 |
| 서버가 바빠요 | 다른 요청이 잠금을 쥐고 있다 | 잠시 뒤 `지금 동기화` |
| 다시 연결해 주세요 | 토큰이 무효(비밀번호를 바꿨거나 `revokeAll`, 6번째 기기) | 비밀번호를 넣고 `연결` |
| 올리지 못한 세션 N개 (기기에는 그대로 있어요) | 서버가 그 세션을 거절했다(길이·형식·`full`) | 데이터는 기기에 있다. 복사로 따로 보관하고, 필요하면 `지금 동기화`로 한 번 더 시도 |
| 보내지 못한 설정 N개 | 설정(체중·운동 시간·단위·증량 폭)을 서버에 못 보냈다 | 연결이 돌아오면 자동으로 다시 보낸다. 급하면 `지금 동기화` |
| 올리지 못한 설정 N개 | 서버가 그 키를 거절했다(크기·키 형식·`full`, 또는 `time`) | `지금 동기화`로 한 번 더 시도. `time`은 기기 시계가 하루 넘게 어긋나 있는데 보정 정보를 아직 못 받은 경우이니 연결을 확인하고 다시 시도. 그래도 안 되면 앱 코드 쪽 문제 |
| 설정이 저절로 되돌아간다 | 다른 기기가 나중에 바꿨다(키마다 갱신 시각이 나중인 쪽이 이긴다), 또는 기기 시계가 크게 틀려 있다(보정은 연결할 때 서버 시각을 받아야 된다) | 기기의 날짜·시간을 자동으로 맞추고 `지금 동기화`. 이전 값은 `workout_v1_replaced_data`에 있다 |
| 다른 기기의 값으로 바뀐 설정 N개 | 이 기기에 이미 있던 값과 서버 값이 달라 서버 값을 따랐다 | 필요하면 설정에서 다시 바꾼다(그때부터는 이 기기 값이 최신이 된다) |
| 읽지 못한 서버 세션 N개 | 서버의 행이 깨졌거나 이 앱이 읽는 형식이 아니다 | 시트 `세션 JSON` 칸을 확인 |
